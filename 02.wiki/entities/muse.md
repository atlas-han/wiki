# Muse

[[meta|Meta]]의 **개인 에이전트(personal agent)**. 본 위키 첫 등장은 [[tech-bridge-zuckerberg-muse-personal-agent]].

> **목표는 세상 모든 사람에게, 자기 목표를 이해하고 24시간 자기를 대신해 일해 줄 아주 유능한 개인 에이전트를 주는 것**입니다. ([[mark-zuckerberg]], 04:20~04:34)

> ⚠️ **이 페이지의 모든 내용은 [[mark-zuckerberg|CEO]] 한 사람의 진술이다.** 제3자 리뷰도 벤치마크도 없고, **사용자 수·가격·성능 수치가 하나도 없다.**

## 형태

| 요소 | 내용 |
|---|---|
| **핵심** | **가상 머신을 뒤에 붙인 장수명(long-lived) 에이전트** |
| **입력** | 프롬프트가 아니라 **프로젝트 또는 목표** |
| **동작** | *"그냥 일한다 — **24시간**, 목표 달성을 도울 때까지 멈추지 않는다"* |
| **밤 공부** | *"성찰을 **메모리로 굳힌다(consolidate)**"* (진행자 표현: *"밤에 공부한다"*) |
| **능동성** | **새 프로젝트를 스스로 제안한다** |
| **UI** | 메인 탭은 채팅, 별도 탭에 **확장 아이디어** |
| **커넥터** | 이메일·메시징·건강 정보·Meta 광고 시스템 — **전부 선택** |
| **모델 주기** | *"대략 매달 의미 있는 업데이트"* |

→ [[goal-level-delegation]] · [[agent-memory]]

**화자는 이 형태가 Meta 고유가 아니라고 명시한다** — *"이건 업계에서 더 넓게 일어나고 있습니다 — [[grokbot|GrokBot]]이든 [[town|Town]]이든 Instinct든, 이렇게 하는 제품이 많습니다."* ⚠️ **ko 자막이 이 열거를 통째로 삭제했다.**

## 경제 모델

| 항목 | 값 |
|---|---|
| **무료 한도** | **주당 1억 토큰** + 가상 머신 (*"컴퓨터가 꽤 많이 딸려 오는 셈"*) |
| **구독** | 선택 가능 |
| **수익원** | **거래 수수료** — *"거래가 무엇이든 그 아주 작은 몫만 뗀다"* |
| **부담 주체** | *"결제하는 개인이 아니라 **그들이 거래하는 기업들**"* |
| **결제** | **Stripe** |

> **이게 실제로 돈을 벌어다 주고 아껴 줄 거라고 우리가 뒤에서 보증하는 것이고, 그렇게 해서 스스로 값을 치를 겁니다.**

→ [[transaction-cut-monetization]]

⚠️ **무료 한도 초과 시 단가와 수수료율이 소스에 없다.**

## 차별화 주장 (셋)

1. **모델을 이 용도에 맞게 바닥부터 설계** — *"다른 회사가 선반에서 뭔가 가져와 조금 사후학습해서 바닥부터 설계한 것만큼 잘할 방법은 없다. 그냥 일어나지 않을 일이다."*
2. **소셜 DNA** — *"관계를 강화하고 삶의 부드럽지만 아주 중요한 부분에서 더 얻도록 돕는 쪽에, 다른 어떤 랩보다 더 주의를 기울일 회사."*
3. **프라이버시와 보안** — 아래.

## 보안 아키텍처 (네 겹)

| 층 | 내용 |
|---|---|
| **[[confidential-vm\|기밀 VM]]** | *"Meta조차 그 안의 내용을 볼 수 없다는 약속을 할 수 있고, **그 약속은 기술적으로 검증 가능하다**"*. [[moxie-marlinspike\|Moxie Marlinspike]]가 전담 |
| **[[sentinel-agent\|센티널 에이전트]]** | 들어오고 나가는 트래픽·데이터를 감시. **프롬프트 인젝션 시도**와 **과잉 공유**를 보고 **사람 검토를 트리거할 권한**을 갖는다 |
| **[[least-privilege-connectors\|최소 권한 커넥터]]** | *"이메일에 연결하면 **읽기 전용으로 시작**한다. 보내게 하고 싶으면 따로 요청하면 된다"* |
| **보안 자격증명 저장소** | *"에이전트는 신용카드·비밀번호·일회용 카드 번호를 **알아서는 안 된다.** 로그인해 달라고 요청했을 때 필요한 만큼만"* |

> **로그인·결제·민감 정보 전송은 매번 승인해야 합니다. (…) Muse 에이전트는 그런 판단을 스스로 내릴 수 없습니다. 그건 시스템과 아키텍처에 꽤 깊이 박혀 있습니다.**

⚠️ **한계가 하나도 논의되지 않는다** — 센티널의 탐지율·오탐, **센티널 자신이 인젝션의 대상이 될 가능성**, 기밀 VM의 검증 방법.

## 함대 학습

> **에이전트가 함대(fleet)의 나머지로부터 익명화된 통찰을 배운다.** (진행자 요약, 화자 동의)

> **지금 업계 대부분은 에이전트를 싱글 플레이어 게임처럼 생각합니다.** (…) **이번 릴리스에서는 대부분 나가지 않지만, 시간이 지나면 중요한 부분이 될 겁니다.**

동기가 도입 문제와 연결된다 — *"AI의 큰 문제 하나는 많은 사람이 그걸로 뭘 해야 할지 모른다는 것"*.

→ [[agent-fleet-learning]] · [[agent-org-adoption]]

⚠️ **"익명화"의 정의·집계 방식·옵트아웃이 전부 없다.**

## 필요로 하는 모델 능력

**코딩**(*"개인 에이전트에서 말하는 것 상당수가 결국 코딩으로 환원된다"* — MMA 비주얼 파이프라인도, 베타 사용자가 만든 Jeopardy 게임도)과 **[[discretion-capability|신중함(discretion)]]** — *"무엇이 민감한지를 백만 개 질문을 하지 않고도 알아야 한다."*

## 베타에서 관찰된 사용 (화자 전언)

- 하루 만에 **홈스쿨링 운영**에 씀
- 12시간 만에 **여행 계획 전체**
- 기술에 회의적인 지인: *"정식 출시하면 **내 Muse 에이전트 계속 쓸 수 있어? 리셋할 거야?**"*

⚠️ **베타 규모·기간·선정 방식이 없다.**

## Meta AI와의 관계

*"별개"* 로 본다 — **Muse는 더 대화적이고 장기 목표를 해석해 오래 일하러 가고**, 명확한 답을 원할 때는 Meta AI. *"시간이 지나면 수렴할 수도 있지만 확신은 없습니다."*

## 두 번째 소스 — 같은 제품, 두 번째 인터뷰 (2026-09-17)

[[tech-bridge-zuckerberg-muse-in-daily-use]]가 들어오면서 Muse는 이 위키에 **소스 두 편을 가진 제품**이 됐다. ⚠️ **두 편은 같은 인터뷰가 아니다** — 앞 편은 [[alex-heath|Alex Heath]]의 65:19 대담이고, 이 편은 **진행자 무명**(자막에 *"Tiff"* 한 번)의 25:09 인터뷰다. **촬영 시점은 두 편 다 미확정이고 선후도 판정할 수 없다.**

| | 앞 편 (09-14 ingest, 65:19) | 이번 편 (25:09) |
|---|---|---|
| 성격 | **선언문** — 15페이지 매니페스토를 푼다 | **짧은 재서술 + 결제·모델·사업 세부** |
| 길이 | **65:19** | 25:09 |
| 사용 사례 | 본인 것 넷 + 베타 전언(홈스쿨링·여행) | **같은 넷**, 세부만 추가 (로봇 사례 신규) |
| 보안 | 네 겹 + *"기술적으로 검증 가능"* | 같은 네 겹 + **결제 층**, 검증 서술은 **사라짐** |
| 경제 | 거래 수수료, **기업이 부담**, **Stripe** | *"가치의 작은 몫 — 커머스 **또는 절약**"*, 부담 주체·결제사 **없음** |
| 오픈소스 | 수단으로 길게 논의 | **한 번도 언급 없음** |
| 모델 | *"대략 매달 의미 있는 업데이트"* | **[[muse-spark\|Muse Spark 1.3]]**, 매달 출하 |
| 함대 학습 | 있음 | **언급 없음** |

### ⚠️ 두 편이 크게 겹친다

**사용 사례 넷(베이킹·등산 허가·MMA 카메라·문명 웹사이트), 아이디어 탭, 주당 1억 토큰, 보안 네 겹, 희귀 질환 롱테일은 전부 앞 편에 이미 있다.** 이 편을 *더 구체적인 사용기* 로 읽으면 틀린다 — **앞 편이 더 길고 더 자세하다**(65:19 vs 25:09). 이 위키가 **같은 화자의 같은 제품에 대한 두 번째 인터뷰**를 받는 것은 처음이고, **그래서 이 편의 값은 새 주제가 아니라 대조에 있다.**

재서술된 넷에서 새로 붙은 세부만 적으면:

| 사례 | 이 편에서 새로 붙은 것 |
|---|---|
| **주말 베이킹** | 딸 이름 **Aurelia**, *"서 있는 프로젝트(standing project)"*, **딸도 피드백을 준다** |
| **로봇 제작** | **앞 편에 없던 사례** — *"여러 주에 걸친 계획을 통째로"* |
| **등산 허가증** | 거의 동일 |
| **MMA 코칭** | **복싱·킥복싱·그래플링을 구분해 낸다**, **Oura 링·운동 데이터 연동** |

서술 각도가 다르다 — 앞 편은 에이전트에게 준 **지시문**을 재현했고(*"매 주말마다 …세팅해 줘"*), 이 편은 **결과 상태**를 말한다(*"앉을 때 모든 게 준비돼 있기를"*). → [[goal-level-delegation]]

⚠️ **두 편 합쳐도 실패·오작동 사례가 0건이다.**

### 앞 편에 없던 것 — 여섯

- **[[agent-persona-naming|이름과 아바타]]** — 화자의 것은 **Agrippa**(로마 장군) + 곰인형 아바타, 진행자의 것은 **Pip**. *"친구가 타이핑하는 걸 보게 됩니다."* **둘 다 이름 짓기가 가장 어려웠다고 말한다.**
- **[[one-time-virtual-card|일회용 가상 카드]]** — 결제 때마다 발급, **판매자는 실제 번호를 못 본다.** 근거가 날카롭다 — *"나도 귀찮아서 평소 카드를 쓴다. **에이전트는 그 추가 수고를 마다하지 않는다.**"*
- **[[nightly-memory-consolidation|매일 밤의 메모리 압축]]** — 앞 편의 *"밤에 공부한다"* 에 **시각·대상·제외 항목**이 붙는다. *"매일 저녁 그날 한 모든 것을 보고 메모리로 압축한다. 사람이 잘 때 생각하고 압축하는 것과 비슷하다."* **자격증명은 제외**되고, **남길 것은 모델이 정한다.**
- **[[muse-spark|Muse Spark 1.3]]** — 이 위키에 **Muse의 모델 이름이 처음** 나온다. *"매달 새 모델을 출하한다."*
- **[[business-in-a-box|비즈니스 인 어 박스]]** · **[[biohub|Biohub]]** — 아래.

그리고 **[[proactive-idea-feed|아이디어 피드]]** 는 신규가 아니다 — 앞 편의 *아이디어 탭* 과 같은 것이고 **같은 문명 웹사이트 예**까지 같다. 다만 앞 편은 이것을 [[agent-fleet-learning|함대 학습]] 질문의 답으로, 이 편은 **도입 문제(*"뭘 해야 할지 모른다"*)의 답**으로 내놓는다.

### 보안 — 앞 편의 네 겹에 다섯째가 붙고, 검증 서술이 빠졌다

| 층 | 막는 것 | 두 편 비교 |
|---|---|---|
| [[confidential-vm]] | 운영자가 내용을 보는 것 | ⚠️ 앞 편의 *"기술적으로 검증 가능"* 이 **이번 편에 없다.** 대신 *"업계에서 견줄 데 없다"* 는 비교 주장만 |
| [[sentinel-agent]] | 민감 데이터 유출 | 앞 편은 *들어오고 나가는* + **프롬프트 인젝션 명시**. 이번 편은 **나가는 쪽만**, 인젝션 **언급 없음** |
| [[least-privilege-connectors]] | 과한 커넥터 권한 | 같은 원칙, 같은 이메일 예 |
| 자격증명 저장소 | 에이전트가 **아는 것** | 동일 |
| **[[one-time-virtual-card\|일회용 가상 카드]]** | **판매자**가 갖는 것 | **신규** |

마지막 둘의 구분이 중요하다 — 저장소는 **에이전트를 향한** 최소 노출, 가상 카드는 **거래 상대를 향한** 최소 노출이다.

### 미래 용도 둘

- **[[business-in-a-box|비즈니스 인 어 박스]]** — *"아이디어만 있으면"* 제작·온라인 존재·**모든 Meta 서비스 연결**·**광고 운영**·백엔드까지. ⚠️ 화자가 **광고 이해관계를 연결하지 않는다.**
- **[[rare-disease-long-tail|희귀 질환 롱테일]]** — 롱테일 관찰 자체는 앞 편(17:43~18:16)에 있다. 이 편이 더하는 것은 **출처([[biohub|Biohub]])** 와 **시장 실패의 구조**, 그리고 **개인 맞춤 치료 설계**라는 주장이다. ⚠️ **검증·규제·책임이 한 마디도 없다.**

⚠️ **이번 편에도 사용자 수·가격·정확도·베타 규모가 없다.** 수치는 **주당 1억 토큰** 하나뿐이고, 그것도 앞 편과 같은 값이다.
