# Ryan Carson

[[untangle|Untangle]] 창업자. 회사 네 개를 만들어 판 창업자이고 직전 회사는 직원 110명쯤까지 컸다(해설 전달). [[ai-engineer|AI Engineer]] New York 발표에서 **빌더 에이전트 20개쯤을 매니저 에이전트 하나로 굴리는 조직도** 를 공개했고, 위키에는 그 한국어 해설 [[tech-bridge-ryan-carson-managing-20-agents]]로 처음 등장한다. ⚠️ 도입부 원음 한 조각을 빼면 전부 해설 전달이고, 위키는 원 발표 · 본인 글을 열지 않았다. ko ASR 표기는 *라이언 카스 · 카슨*.

## 조직도 (해설 전달)

- 사람(우선순위 · 고객) → **매니저 에이전트**([[devin|Devin]] 세션 하나, *절대 코드를 쓰지 않는다*, 주로 음성으로 대화) → 티켓 보드(Linear, 티켓 하나 = PR 하나) → **빌더 에이전트** 5~25개(보통 20개쯤) → 리뷰 에이전트(왕복 최대 세 번) → QA 자식 에이전트 → 기능을 써 보는 **영상** → 사람의 *Ship it*. → [[manager-bot-coding-agent-split]]
- 15분마다 스크립트가 매니저에게 모든 빌더 세션을 확인시킨다 — 에이전트가 알아서 챙기리라 믿지 않는다. → [[scheduled-agent-automations]]
- 빌더 수의 상한은 사람이 매니저와 대화하며 상황을 파악하는 속도다. → [[agent-attention-management]]
- 팀이면 사람마다 매니저 하나(많으면 둘), 매니저끼리 대화하고, **머지 큐 매니저** 세션이 순서를 조율한다(예: 데이터베이스 마이그레이션 번호 충돌).
- 9월 글의 조합: 엔지니어링 매니저는 [[claude-opus-5-5|Opus 5.5]], 여기에 Devin과 Linear, 로컬 개발 없음.

## 클라우드 · 채용

- *"로컬 개발은 돌을 두드리며 끙끙대는 것이고 클라우드 에이전트는 로켓에 타는 것이다."*(05:48~05:52) — 8월에는 클라우드 비중 95%라는 단서. 이런 공장을 직접 만들지 말고 만들어진 도구를 사라고 권한다. → [[cloud-agent-delegation]]
