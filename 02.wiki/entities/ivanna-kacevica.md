## 위키에서 알려진 사실

- [[agent-skills]]의 **첫 실무자 관점** 제공자. 스킬을 쓸 신호를 둘로 나눈다 — **반복**, 그리고 **한 번만 하지만 자동화하고 싶은 워크플로**(쓰고 지우는 스킬).
- *"MD 파일은 사실 그렇게 무해한 파일이 아닙니다."* — 스킬 파일을 [[prompt-injection]]의 공급망 벡터로 지목. 공식 출처(Google의 Flutter·Dart 스킬, 패키지 maintainer 스킬)와 **숨은 Unicode 지시** 확인을 처방.
- 자기 역할을 *"카피라이터보다는 관리자"*로 규정. skill creator로 만들되 **확인·수정·통제**를 유지.
- 추천 스킬 5개: Skill Creator · Code Review + PR triage 교차 확인 · 새 기능 스캐폴딩(description에 "use when" 명시) · Flutter Row/Column 레이아웃 · 스크린샷 시각 QA.
- 에이전트 코드 리뷰의 남은 한계를 정확히 짚는다 — *"코드가 좋은지는 평가할 수 있지만 그 코드가 필요한지는 항상 판단할 수 없다."*
- 강한 모델도 컨테이너+패딩 조합을 선호하는 이유를 **보상 구조**와 **Flutter 학습 데이터 격차**(Python·JavaScript 대비)로 설명.
- 세 대의 기계에서 Claude·Codex·Antigravity를 병렬로 돌리고 **서로 인계**시키며, 한도를 다 쓸 때까지 일한다. 풀타임 본업 뒤 저녁·주말에 RevenueCat Shipaton 참가작을 에이전트 팀으로 개발.
- 동기를 솔직하게 게임화로 인정 — *"룰렛은 안 좋아하고, 토큰을 다 써버리는 걸 좋아해요."*
- 커뮤니티 Flutter 스킬 목록을 **최소 2주에 한 번** 점검한다.
- 머신러닝·데이터 엔지니어링 배경. AI 회의론자였던 적이 없다고 말한다.

> 이 인터뷰의 효과 진술("1년 넘게 잘 됐다", "정말 좋은 결과")은 모두 **일화**이며 측정치가 없다.
