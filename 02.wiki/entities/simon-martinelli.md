# Simon Martinelli

스위스의 엔터프라이즈 Java 컨설턴트. **AI Unified Process**의 저자로, [[tech-bridge-sdd-enterprise-lessons]]에서 엔터프라이즈 팀과 레거시 현대화에 [[spec-driven-development|SDD]]를 적용한 경험을 발표했다. 본 위키 첫 등장.

> ⚠️ **이름 표기.** 자막에서 이름은 사회자의 *"Thank you so much, Simon."*(27:24)뿐이다. 도입 일화의 클럽 회원은 *"Hey Sam"*(00:55)이라 부른다(애칭인지 ASR인지 미확정). **성 "Martinelli"는 설명란에만 있다** — 이 페이지는 설명란 표기를 따른다.

## 이력 (자막에서, 화자 진술)

- *"I'm doing mostly Java development. I'm a consultant in Switzerland for 17 years"*(01:44~01:47) — 보험·도매·소매·정부·대기업의 **비즈니스 애플리케이션**: *"I don't do tools, I don't do products, I do business applications."*(01:58~02:02) ⚠️ ko는 "17년"을 **"17살"** 로 옮겼다.
- 엔터프라이즈 애플리케이션 현대화 *"about eight years now"*(10:02~10:05). 현재 스위스 최대 도매업체의 ERP 현대화(07:14~07:19), 스위스 의회의 사례관리 소프트웨어 PoC(26:09~26:21), 같은 프로세스로 고객 6곳(09:23~09:26).
- 2000년대 초 스위스 철도에서 system use case를 썼다(05:02~05:08).
- 1997년부터 고향 스포츠 클럽의 대회 운영 소프트웨어를 만들어 왔다(00:23~00:40). 2024년 가을 AI 도구로 클럽의 자원봉사자 관리 시스템을 만든 것이 SDD로 간 계기(00:48~01:41).
- Tessl의 AI Native Dev 사이트에서 Simon Maple의 글로 AI 시대의 SDD를 접했다(02:07~02:20).

## 이 위키에 무엇을 들여왔나

- **AI Unified Process** — 스펙 = system use case + entity model, plan/task 단계 생략, 그 사이를 스킬이 채움, brownfield는 역설계. → [[ai-unified-process]]
- **AI 시대의 아키텍처 기준** — 마이크로서비스 500개도 거대 모놀리스도 아닌 self-contained system. → [[self-contained-systems]]
- **"everything shifts left to requirements engineering"**(26:43~26:45), 팀 축소(5~7명 → 1~2명), 스프린트 대신 continuous flow, PR 없이 trunk-based + peer review.
- **도구 비판** — [[kiro|Kiro]]·[[github-spec-kit|Spec Kit]]·BMAD는 *"too developer centric"*(03:20~03:24).

⚠️ 자기 프로세스의 저자가 한 발표이고, 효과 수치(데모 1분 30초, 팀 규모, near deterministic)는 측정 없이 말해진다. 행사는 설명란 링크상 Tessl의 AI DevCon으로 보이나 자막엔 행사명이 없다.
