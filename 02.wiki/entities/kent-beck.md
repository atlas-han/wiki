# Kent Beck

익스트림 프로그래밍(XP)의 창시자, JUnit 계열 프로그래머 테스트 프레임워크와 테스트 주도 개발(TDD)로 알려진 소프트웨어 엔지니어·코치. [[tech-bridge-kent-beck-craft-augmented-development]]에서 정부·군 청중에게 **증강 개발(augmented development) 시대의 craft** 를 이야기했다. 본 위키 첫 등장.

> ⚠️ **경력은 모두 강연 속 본인 진술이다.** *"programmer testing frameworks like JUnit was my original invention. I refined it with Eric Gamma"*(03:43~03:51), TDD는 *"I can't claim to have invented TDD (…) I maybe rediscovered it"*(04:51~04:59 — 1957년 책의 *"check items"* 를 근거로), *"extreme programming is my baby"*(05:01~05:05), 애자일 선언문 *"the first signatory (…) alphabetically"*(05:13~05:16). 설명란은 *"TDD의 창시자"*, *"첫 번째 서명자"* 라고 줄여 쓴다.

## 지금 하는 일 (자막 근거)

- *"I'm working with uh one of the frontier labs"*(05:36~05:42) — 프런티어 모델 팀이 어떻게 일해야 하는지를 돕는다. ⚠️ **어느 랩인지 미발화.**
- *"programming hardcore every day for maybe the last 18 months"*(18:28~18:31) — Gene Kim·Steve Yegge의 데모를 보고 돌아왔다. 프로젝트마다 *project two, three, four* 로 다시 시작한다(19:07~19:20).
- 고참의 역할은 코칭 — *"young engineers make exactly the same young engineer mistakes (…) since the time of the Romans"*(12:32~12:39).

## 강연의 두 그림

- [[features-vs-futures]] — 기능을 낼 때마다 미래 선택권(futures)을 태운다. 기능 사이에 멈춰 futures를 되돌려라. 프로젝트 가치 = features + futures.
- [[effort-output-outcome-mission]] — 노력 → 산출 → 결과 → 미션. 코드 줄 수·PR 수는 노력·산출의 측정. *"I think Goodart was an optimist."*(48:41)

## 태도

- **AI를 "지니(genie)"라 부른다** — *"it grants your wishes, but it ends up not being what you really wanted"*(06:47~06:55). *"Now that the genie is better at coding than humans"* 는 *"boulder dash"*(07:39~07:49). 산출물에는 *"an adversarial view"*(10:29~10:32).
- **그래도 즐긴다** — *"I absolutely love programming with the Genie"*(18:42~18:46), 어셈블리 구현을 시키며 *"figuring out all the different ways I can torture the genie is just so entertaining"*(39:48~39:53).
- **자기 작업을 깎는다** — craft 책 세 권은 *"completely obsolete and should be thrown away"*(13:40~13:44), XP에서 *"If I said anything creative (…) it was definitely a mistake"*(30:00~30:07), Casals 일화는 *"The story's made up"*(23:56).
- [[spec-driven-development]]에 반대 — *"That's exactly waterfall development"*(35:48~35:50). 다크 팩토리는 *"always goes off the rails. Always."*(31:14~31:17). 형식 기법(Lean)에도 두 한계를 든다 → [[ai-formal-verification]].
- 멘토는 Ward Cunningham(*"Ward invented the wiki"*, 33:08~33:13).
