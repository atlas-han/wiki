# Tech Bridge — 토탈 리콜: 에이전트 메모리와 하네스 엔지니어링

[[tech-bridge|Tech Bridge]]가 한영자막을 입힌 **57:08 컨퍼런스 워크숍 현장 녹화**(공식 챕터 17개). [[oracle|Oracle]]의 개발자 애드버킷 [[ignacio-martinez|Ignacio Martinez]]가 **오전 9시 세션**에서 약 38분 강의하고, 나머지는 실습 안내·데모·Q&A다. 제목의 *토탈 리콜*은 워크숍에서 만드는 **데모 앱 이름**이다(*"this total recall port"*, 46:12). 한 줄 테제:

> **추론은 빌려 쓰고(동결돼 있고 교체 가능), 메모리·도구·인식은 우리가 소유한다. 하네스 엔지니어링의 목표는 비결정적인 모델에서 신뢰할 수 있고 반복 가능한 결과를 얻는 것이다.**

> ⚠️ **당사자 발표다.** 발표의 약 3분의 1이 Oracle 제품(DBFS · LangChain Oracle DB · in-database embeddings · 컨버지드 DB · Oracle Agent Memory Package · OCI Generative AI)이고 **측정값이 하나도 없다** — *"시장에서 유일한 컨버지드 데이터베이스"*(21:31~21:37), OAMP *"단 한 줄의 코드로"*(28:32~28:38), HNSW로 *"2,000개든 10,000개든"*(49:59~50:07), 도구 호출 상한 *"8에서 12"*(52:49~52:53)는 **모두 주장·개인 경험**이다. 강의 중 예고한 **세 에이전트가 한 파일의 카운터를 동시에 올리는 경주**(16:54~17:13, *"물론 답은 알지만"*)는 **녹화에 결과가 없다** — 실습 1시간 15분(43:54~43:57)이 녹화 밖이다.
>
> ⚠️ **화자 이름이 자막에 한 번도 나오지 않는다.** 설명란의 *"Ignacio Martinez"* · X `nacho_martinez` 를 따른다. 자막은 *"오라클에서 7년, 그중 약 4년 개발자 애드버킷"*(01:27~01:35)과 *"[[andrew-ng|Andrew Ng]]과 에이전트 메모리 강좌를 냈다"*(01:47~01:50)까지.
>
> ⚠️ **행사·시점 미확정.** 회의장 Wi-Fi *"AI.gineer"*(39:39), 슬라이드는 *"AI Engineer"*(40:48)로 간다, *"Oracle 부스, 매일"*(56:09~56:15) → **[[ai-engineer|AI Engineer]] 계열 다일(多日) 컨퍼런스**로 보이나 **회차·연도·도시는 말하지 않는다.** 시간 단서: 파일 vs DB 딜레마가 *"1월부터"*(13:12~13:16) · *"지난 6개월"*(10:53~10:56). 데모 모델이 *"Grog/Groq 4.1 fast reasoning"*(52:41~52:44, ⚠️ xAI Grok 4.1 Fast로 읽힘, 미확정)이라 **이 위키가 이미 받은 [[grok-4-6]]보다 이전 세대** — **업로드보다 꽤 이전 녹화일 수 있다**는 가능성만 표시한다.
>
> ⚠️ **"하네스 7계층"은 음성으로 다 열거되지 않는다** — 아래 표. 설명란·챕터의 *"7가지"* 는 **슬라이드에만** 있다.

ASR·ko 보정: ⚠️ **ko가 발표의 두 중심어를 한 단어로 뭉갠다** — *harness* 는 대부분 **"환경"**(그 밖에 *"프레임워크·기본 틀·프레임"*, 사물로서 *"하네스를 착용한 채로"*), 그리고 **Umwelt도 "환경"**(31:15·32:17). **ko만 읽으면 하네스와 움벨트를 구분할 수 없다.** *worktrees* → **"나무를 다루는 일"**(15:12), *ACID* → **"산성"**, *embeddings* → **"상감(세공)"**, *retrieval* → **"회복·복구"**, *weights* → **"무게"**, *frozen model* → **"겨울왕국"**(35:24), *agents* → **"자치령 대표"**(12:37·43:02), 동료 *Valentine* → **"발렌타인데이·애인"**, *route* → **"표류"**, 라우팅 회사의 과금 *절감액의 10%* → **"토큰 가격의 10%"**, *"이름을 밝히지 않겠다"* → **"이름을 밝히겠습니다"**(20:49, 부정 반전). ✅ 반대로 **en-orig가 깨뜨린 이름을 ko가 바로 적는 자리**가 있다 — *Andrew Ang/Yang* → **앤드류 응**, *Asian memory* → **에이전트 메모리**, *envelop … von Wexul* → **움벨트 · 야콥 폰 우엑스퀼**, *354 years* → **30~40년**. **ko는 en-orig가 아니라 교정된 en 변종 트랙에서 번역된 것으로 보인다**(추정). 전체 목록은 `01.raw/articles/2026-09-23_토탈 리콜 - 에이전트 메모리와 하네스 엔지니어링을 마스터해보세요.md`.

## 에이전트 = 모델 + 하네스, 추론은 빌린다

> 저에게 있어 AI 에이전트는 본질적으로 모델 (…) [+ 하네스]. **모델 자체가 추론의 근거가 될 것입니다. 나머지는 모두 [하네스]가 될 것입니다.** (06:39~06:52)

> 추론은 (…) [우리가 통제하지 못하는] 부분입니다. [막대하게 보조되는] 부분 **우리가 빌린 것.** 만약 당신이 저와 같다면, **모든 구독 서비스에 가입했습니다** (…) 그다음에는 **메모리, 도구, 그리고 인식** 우리가 특정한 것을 얻는 **맞춤 설정 기능.** (07:30~07:59)

> [하네스 엔지니어링]의 목표는 (…) **언제나 믿을 수 있고 예측 가능합니다.** 하나의 모델이 추론 방식은 **매우 비결정적입니다.** (08:04~08:16)

> 하네스 그들은 다음과 같은 모델을 기반으로 구축합니다. **상호 교환 가능합니다.** 하나만 있으면 됩니다 (…) 공통 인터페이스 **OpenAI 또는 (…) Anthropic API 사양** (10:03~10:14)

정의문은 *"대규모 언어 모델로 추론하고, DB나 파일로 메모리를 보강하고, 도구로 행동을 확장하고, 입력으로 환경을 지각하는 자율적 개체"*(06:59~07:20, en-orig 대조). → [[agent-harness-design]] · [[harness-engineering]]

**이 위키의 하네스 정의 계보에 한 줄이 붙는다.** 09-23 [[tech-bridge-lopopolo-agent-harness|Lopopolo 편]]의 진행자 정의(*하네스 = LLM이 아닌 모든 것*)와 **글자까지 같은 넓은 정의**인데, **결론이 정반대로 간다**:

> ⚠️ Contradiction: **하네스를 만드는가, 고정하는가.** [[ryan-lopopolo|Lopopolo]]는 *"저는 하네스를 만들어 본 적이 없습니다"* — 하네스(Antigravity 같은 것)는 **고정**하고 도구·컨텍스트에만 투자하라([[tools-and-context-over-harness]]). Martinez는 **모델이 고정(동결·임대)** 이고 **하네스가 우리가 만드는 것**이라며, 워크숍 전체가 *"모델만으로 시작해 하네스 층을 하나씩 더하는"*(44:26~44:34) **하네스 직접 구축**이다. ⚠️ 두 사람의 "하네스"가 가리키는 범위가 다르다 — Lopopolo의 고정 대상은 **에이전트 제품**(Antigravity·Claude Code), Martinez가 만드는 것은 **메모리·스토리지·시맨틱 레이어·컨텍스트 조립**으로, 이는 Lopopolo가 *"도구와 컨텍스트"* 라 부른 쪽과 **상당 부분 겹친다.** 이 위키는 **어휘의 충돌이지 처방의 충돌은 아닐 수 있다**고 읽되, 판정하지 않는다.

**에이전트 스택 5계층**(03:07~04:22): 애플리케이션 · **데이터** · 모델 · 인프라 · 컴퓨트. *"데이터를 제외한 네 계층은 점점 상품화된다"*(03:48~03:58) → *"우리가 가장 많이 통제하는 것은 데이터"*(04:11~04:13). 데이터 계층 안: **게이트웨이·MCP**(맨 아래, 04:38~04:46) 위에 메모리·시맨틱·retrieval·컨텍스트·도구와 스킬(05:01~05:15). [[model-harness-knowledge-stack|Google 편의 모델·하네스·지식 3계층]]과 나란히 두면 — **Google은 모델 선택을 층으로 세우고, Oracle은 모델을 "통제 밖"으로 치우고 데이터를 세운다.** 둘 다 자사 제품이 있는 층을 중심에 둔다.

**AI 애플리케이션의 네 형태**(05:51~06:28): LLM 챗봇(수동) · RAG(반수동) · LLM 워크플로(자동화 → 신뢰성) · AI 에이전트(자율성 → 유연성). Claude Code·Codex류는 **자동화 + 자율성의 조합**(08:29~08:45). → [[workflow-vs-agent]]

## ⭐ 파일 vs 데이터베이스 — 워크트리는 트랜잭션의 대용품이다

> [파일 극대주의자와 DB 극대주의자] (…) **둘 다 옳습니다.** (13:19~13:32)

> 파일이 매력적인 이유는 (…) **모델들이 즐겨 찾고** (…) **POSIX 의미 체계**를 따릅니다. (14:18~14:25) — en-orig *"they match the model's instincts"*(13:46)

> [파일에는] **[트랜잭션] 일관성**[이 없습니다]. (…) **한 번에 8, 16, 32개의 에이전트** (…) 문제는 파일들이 (…) **동시에** [수정될 수 없다는 것입니다]. (14:36~15:00)

> **[워크트리]. [워크트리]. 예. 정확한.** (…) **다른 작업 트리를 생성합니다.** (…) 구현이 끝나면 **메인 브랜치**로 [병합합니다]. (…) **[트랜잭션] 일관성이 없는 것을 우회하는 방법**입니다. (15:12~15:36)

> 하이브리드 시스템이 더 효과적입니다. (…) **단기 기억은 파일에**, 그리고 무언가가 **장기 기억으로 승격**되어야 할 때, 예를 들어 **사용자 선호도**는 (…) [더 구조화된] 데이터베이스로 (17:46~18:07)

→ **[[files-vs-database-agent-memory]]**

⭐ **이 위키가 git worktree를 본 것은 병렬 작업의 격리 수단**([[agent-swarm]]·[[ai-native-sdlc]])이었다. 이 소스는 같은 것을 **저장 계층의 결함(트랜잭션 없음)을 사람이 우회하는 패턴**으로 다시 읽는다 — *동시 쓰기가 불가능하니 가지를 나눠 쓰고 나중에 병합한다.* 그렇게 보면 **머지 충돌은 트랜잭션 격리가 없어서 사후에 치르는 비용**이다. ⚠️ 이 해석은 화자가 **DB를 파는 자리**에서 나왔다 — 워크트리가 제공하는 **리뷰 가능한 diff·브랜치 단위 롤백**(DB 트랜잭션에는 없는 것)은 말하지 않는다.

그리고 [[file-system-agent]](Vercel, 09-19)와 **같은 관찰, 다른 결론**이다 — 둘 다 *파일은 모델이 가장 잘 다루는 인터페이스* 라는 데서 출발하고, Vercel은 **샌드박스에 파일을 붓고 끝**, Oracle은 **파일 인터페이스를 DB 위에 올린다(DBFS)**.

## RAG 파이프라인의 파편화 → 컨버지드 DB (당사자 주장)

파이프라인(20:07~20:39): 토큰화 → 임베딩 → 중복 제거·정규화·PII 가리기 → 텍스트·JSON 메타데이터·32비트 dense 벡터가 **각기 다른 DB로** → *"매우 높은 데이터 동기화 [로직 오버헤드]"*(21:01~21:05). 검색 쪽은 **바이인코더 → 벡터 스토어 → 크로스인코더 리랭커**(19:11~19:55). → [[retrieval-augmented-generation]]

처방은 **한 DB에 모든 형(JSON·관계·공간·그래프·벡터)을** — *"우리는 시장에서 유일한 컨버지드 데이터베이스"*(21:31~21:37). **보안 논거**가 붙는다:

> 데이터를 한 곳에. 그러므로, **당신은 단 한 가지만 걱정하면 됩니다. 공격 벡터.** (…) **5개의 데이터베이스를 업데이트**하는 것에 대해 [걱정할 필요가 없습니다]. (22:04~22:14)

⚠️ **보안 논거는 반쪽이다** — 공격 표면이 **하나로 줄면 폭발 반경은 전부**가 된다. 이 위키의 [[company-brain]]·[[no-silent-write]]가 세운 *데이터·도구 접근 제어* 논점(누가 무엇을 읽는가)은 나오지 않는다. 그리고 데모에서 화자는 **Codespaces 포트를 public으로 바꿔** 공용 게이트웨이로 앱을 연다(46:17~46:31) — 워크숍 편의이지만 **권한·인증 이야기는 없다.** in-database embeddings의 논거(*"제3자 서비스를 호출할 필요가 없어 데이터 보존·보안에 적합"*, 18:41~18:58)가 이 소스에서 보안을 **구체적으로** 다룬 유일한 자리다.

⭐ **"미해결 질문"을 카드의 독립 칸으로 둔 것**이 이 위키가 본 메모리 구조 중 처음이다 — [[context-resets-and-compaction]]의 압축이 *무엇을 남기나* 의 문제였다면, 여기서는 **"아직 끝나지 않은 것"** 을 요약과 따로 보존한다. ⚠️ 카드가 실제로 압축 후 성능을 지키는지 측정은 없다.

## Context rot — 창을 늘리면 안 되는 이유

> **"1500만 컨텍스트 윈도우"** 아직은 불가능하지만, 어떤 사람들은 그것이 [해결책이라고] 실제로 믿습니다. (…) [컨텍스트 창은] **단기 기억의 한 유형**입니다. (25:09~25:24)

> [**context rot**] 또는 **시간이 지남에 따라 맥락이 저하됨** (…) [컨텍스트 창에] 많이 놓을수록 (…) **[어텐션]을 덜 받게 될 것입니다. 각각의 것들에 대해** (25:34~25:48)

> **주의 매트릭스** (…) **제곱에 비례하여 증가합니다.** (…) **나머지 토큰 각각에 대해 토큰 하나씩** (…) 행의 수 (…) 컬럼이 문제입니다. (26:35~26:57)

→ **[[context-rot]]**

⚠️ **두 논거가 섞여 있다** — ① *많이 넣을수록 항목당 주의가 줄어든다*(품질), ② *어텐션 행렬이 n²로 커진다*(비용). 화자는 ②를 ①의 원인처럼 잇지만 **제곱 비용은 계산량의 문제이지 주의 희석의 증명이 아니다.** 그리고 이 위키의 [[long-context-agents]](MiniMax, 09-08)는 **창을 늘리는 쪽이 처방**이었고, [[sparse-attention]]은 바로 ②를 줄이는 기술이다. → [[context-rot]]의 ⚠️ Contradiction.

## ⭐ 움벨트 — 시맨틱 레이어는 에이전트의 지각 렌즈다

> **세상의 살아있는 유기체는** (…) **렌즈를 통해 본 현실** (…) **우리의 모든 경험은 이 렌즈를 통해서 보는 거죠** (31:23~31:44)

> 그 [에이전트]는 인간의 감각을 가지고 있지 않지만 (…) **의미론적 렌즈를 통해 당신이 요청하는 모든 것이 걸러지는 곳입니다.** 그리고 이 렌즈는 (…) **당신이 그를 훈련시키는 것과 (…) 맥락으로 제공해 주[는 것]** (31:48~32:04)

> **아이처럼** [처음 함께 일하는 사람에게는] **모든 것을 구체적으로 명시해야 합니다.** (…) **진정한 부족 지식[tribal knowledge]** (…) **데이터가 어떻게 모델링되고, [쿼리가] 어떻게 실행되는가**, **메타데이터**; 이 모든 것들이 안에 있습니다 의미 계층. (32:43~33:13)

→ **[[agent-umwelt]]**

**이 위키의 "회사 고유 지식" 논의에 지각론의 틀을 준다** — [[company-knowledge-moat]](Vercel: 에이전트가 grep하는 시맨틱 레이어)와 [[company-brain]](PromptQL: 사람이 읽는 위키)이 *무엇을 넣을까* 였다면, 움벨트는 **에이전트가 볼 수 있는 세계의 경계가 곧 그 렌즈**라는 것 — 렌즈 밖의 것은 에이전트에게 **틀린 게 아니라 존재하지 않는다.** ⚠️ 이 확장은 위키의 읽기다. 화자는 비유를 **동료 간 암묵지** 설명에 쓰고 멈춘다.

## 툴박스 패턴 — 도구도 검색 대상이다

> **툴박스 패턴과 스킬 박스 패턴** (…) **정말 필요한 것들을 넣고** (…) **각 반복에서** (…) **이것이 맞는지 확인할 수 있습니다.** (…) 그렇지 않다면 (…) **간단히 빼내실 수 있습니다. 일시적으로.** (34:19~34:53)

> [에이전트 루프의 매 반복마다] **맥락을 구성할 것입니다.** (35:05~35:08)

Q&A에서 구체화(48:38~51:34): 수천 개 도구는 **HNSW 벡터 인덱스**로 — *"일상 도구(파일 읽기·쓰기·grep)는 보통 100~1,000개를 넘지 않는다"*(49:34~49:49). 두 회사의 도구 설명이 비슷해 헷갈리면 **LLM으로 도구 설명을 보강해 분리도(separability)를 높인다** — NER은 *"원시적"*(51:18~51:20). 이 개념은 *"Andrew Ng과의 강좌에서 소개했다"*(48:46~48:51).

→ **[[toolbox-pattern]]**. [[agent-tool-design-practices]]가 *"도구가 너무 많다 → 선택 과부하"* 로 남긴 칸에 대한 **검색 쪽 처방**이고, [[agent-skills]]의 progressive disclosure를 **도구에도** 적용한 형태다.

## 지속 학습 3종과 스킬 승격

> 방법은 있습니다 (…) **[가중치]** (…) **[표현(representation)] — [임베딩과 리랭킹]**, 그리고 **컨텍스트 창에서도** (…) **이것들은 세 가지 [지속 학습 기법]입니다.** (35:27~35:47)

워크숍은 **컨텍스트·토큰 공간**에 집중한다 — *"더 쉽고 더 저렴하다. 여기 백만장자는 없을 테니"*(35:47~36:03). → [[continual-learning]]

> [승격한다면] 예를 들어, [스킬]이라면 (…) **증류를 통해 원본보다 더 나은 [skill.md]** (…) **이전 버전은 은퇴시키고, 새 버전으로 업데이트** (36:47~37:04)

승격 대상은 *"서너 시간 들여 하루 종일 성공시킨 워크플로"*(36:24~36:34), 결과는 **나의 어조·업무 방식·선호**(*이 라이브러리가 마음에 든다, 이 DB 엔진이 버그가 적었다*)가 들어간 스킬(37:04~37:29). → [[skill-self-improvement]]

⭐ **이 위키의 "승격" 삼각형이 완성된다** — [[skill-self-improvement]](task-observer: **실패**에서, **사람 게이트**), [[query-to-skill-distillation]](Vercel: **성공한 질의**에서, **게이트 없음**), 그리고 **이 소스: 성공한 긴 세션에서, 증류로 새 버전을 만들고 옛 버전을 은퇴** — **버전 교체**가 명시된 것이 처음이다. ⚠️ **승격 게이트가 무엇인지(사람이 보는가, eval이 있는가) 말하지 않는다.** 옛 버전 은퇴는 [[skill-evals]] 없이는 **회귀를 모른 채 덮어쓰기**가 될 수 있다. 같은 "승격"이 **메모리**에도 쓰인다(단기 파일 → 장기 DB, 17:53~18:07) — 화자에게 승격은 **수명이 긴 저장소로 옮기는 일반 동작**이다.

> [Grok 4.1 Fast reasoning — ⚠️ 미확정] (…) **8에서 12 사이의 값을 발견했습니다. 최대 [도구 호출] 횟수 포기하기 전에** (52:41~52:53)

> 제가 정의하고 싶은 것은 (…) **[히스테리시스] 변수** (…) **[하네스]가 모델에게 가질 인내심** (53:17~53:25)

→ [[linear-vs-closed-loop-harness]] — 빌리의 폐루프는 *~5회*, 이 소스는 **8~12회**, 그리고 그 값을 **모델마다 다른 하이퍼파라미터로 이름 붙인다.** 데모는 같은 질문을 **16단계**에서, 다시 **2단계**에서 풀었다(47:30 · 53:03~53:08) — **분산이 크다는 것 자체가 상한이 필요한 이유**다. ⚠️ *hysteresis* 는 공학에서 **이력 의존**을 뜻한다. 화자의 용법(인내심 상한)은 **비표준**이고 이 위키는 판정하지 않는다.

> **모델에 결함이 있는 경우** (…) **라우터** (…) 어려운 문제는 **[프런티어] LLM**으로 (…) **간단한 문제의 경우, 개방형 가중치 SLM을 할당합니다.** (53:29~53:44)

> **미래는** (…) **각 유형별 소규모 전문가** [의 혼합] (…) [1억 파라미터 모델] (…) **라우팅을 구현할 수 있습니다. [하네스] 내의 모델.** (53:58~54:32)

→ [[model-mixing-economics]] — 라우팅을 **하네스의 한 기능**으로 두고, 그 사업 모델(*"절감해 드린 토큰의 10%를 받는다"*, 54:39~54:45)까지 준다. ⚠️ ko는 이를 *"토큰 가격의 10%"* 로 바꿨다.

## 이 소스가 이 위키에 더한 것 / 뺀 것

**더한 것:**

- **저장 계층이 하네스의 첫 층**이라는 관점 — 이 위키의 하네스 소스는 루프·도구·컨텍스트·검증이었고 **스토리지를 층으로 세운 것은 처음**이다. → [[files-vs-database-agent-memory]]
- **워크트리 = 트랜잭션 부재의 우회책**이라는 재해석.
- **context rot**라는 이름 — 이 위키에 [[context-anxiety]](모델 행동)·lost in the middle(09-23)은 있었지만 **열화 자체의 이름**은 처음. → [[context-rot]]
- **움벨트**로 시맨틱 레이어를 설명하는 틀. → [[agent-umwelt]]
- **도구 검색(툴박스)** · **스킬의 버전 교체형 승격** · **인내심 예산**.

**무엇이 사라졌는가** (09-18 재방문 대조 규칙):

- **평가가 없다.** 하네스의 목표가 *"신뢰할 수 있고 반복 가능한 결과"* 인데 **그것을 어떻게 재는지**가 한 번도 나오지 않는다 — 데모의 16단계 vs 2단계가 **반복 불가능성의 실물**인데도 지나간다. [[skill-evals]]·[[verifiable-goals]] 부재.
- **틀린 기억의 무효화** — [[agent-memory]]의 오래된 미해결(Apex/Ivy 사례)이 **여기서도 비어 있다.** 승격은 있고 **강등·삭제는 없다.**
- **보안** — 위 컨버지드 DB 절. *"단일 공격 벡터"* 한 문장과 in-DB 임베딩뿐.
