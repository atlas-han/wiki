# Tech Bridge — AI를 위한 만능 리모컨 (ACP)

[[tech-bridge|Tech Bridge]]가 한영자막을 입힌 10:32 단독 발표. 화자는 [[block|Block]]의 [[alex-hancock|Alex Hancock]] — [[goose|Goose]] 메인테이너이자 **MCP Rust SDK 메인테이너**이고 최근 **ACP** 작업을 시작했다. 한 줄 테제:

> **MCP는 "에이전트 → 도구" 방향을 표준화했다. "클라이언트 → 에이전트" 방향에는 아직 표준이 없고, 그래서 하네스마다 인터페이스가 제각각이다 — 그 자리를 [[agent-client-protocol|ACP]]가 채운다.**

ASR 보정: *IP*(지적재산권)가 ko에서 **"IP 주소"** 로, *Goose* 가 **Goose·구스·거위** 세 표기로, *client*(클라이언트 소프트웨어)가 **"고객"** 으로 — 특히 **결론 문장**(*"클라이언트의 품질이 올라갈 것"* → *"고객들의 질이 향상"*)에서. *"vibe coded"* 는 ko에서 **통째로 소실**됐다. 전체 목록은 raw 헤더에 있다: `01.raw/articles/2026-09-12_AI 에이전트를 위한 만능 리모컨, ACP를 소개합니다.md`.

## 문제 — 하네스는 많은데 리모컨이 하나씩이다

화자의 문제 제기는 **공급이 아니라 접근**이다.

> 좋은 하네스가 정말 많습니다 — 랩에서 나온 것, 여러 회사에서 나온 것… 그런데 **그것들에 접근하는 인터페이스가 대개 맞춤형이거나 주문 제작**입니다. 최악의 경우, 어떤 하네스는 **그것을 제어할 수 있는 클라이언트 애플리케이션이 문자 그대로 하나뿐**일 수도 있죠. (01:10~01:45)

비유는 웹이다:

> **모든 웹사이트에 접속하는 데 단 하나의 브라우저, 단 하나의 프로토콜만 써야 한다면** 어떻겠습니까. **브라우저의 현실이 그랬다면 개방형 웹 같은 건 없었을 겁니다.** (01:45~02:06)

이 위키가 [[agent-harness-design|하네스]]를 **프롬프트·컨텍스트·도구를 조립하는 층**으로 다뤄 왔다면, 이 소스는 거기에 **그 층을 바깥에서 어떻게 조종하는가**라는 축을 새로 붙인다.

## 처방 — 표준은 생태계와 시장을 만든다

> **표준의 핵심은 그것이 생태계와 시장을 만든다**는 겁니다. (02:08~02:13)

> **MCP의 가장 강력한 점은 MCP 자체의 무엇이 아니라, 모두가 MCP를 쓴다는 것**입니다. 그래서 전 세계에 **수천~수만 개의 서버**가 있고, 모든 에이전트가 거기 연결해 다른 시스템에서 일을 할 수 있습니다. (02:31~02:47)

**표준의 가치를 기술적 우수성이 아니라 채택의 보편성에 두는 진술**이다. → [[standards-as-market-makers]] · [[model-context-protocol]]

그리고 방향의 빈자리를 짚는다:

> **클라이언트 소프트웨어가 에이전트에게 무엇을 할지 알려주는 쪽** — 과제를 주고, 무엇을 작업할지 말하고, 업데이트를 받는 쪽 — 에는 **아직 좋은 해결책도 표준도 없다**고 봅니다. (02:49~03:05)

## ACP의 형태

| 요소 | 내용 |
|---|---|
| **출처** | [[zed|Zed]]와 JetBrains가 제안. 동기는 *"에디터에 고품질 클라이언트 구현을 하나만 작성해 어떤 하네스든 제어"* |
| **Goose 팀의 판단** | *"에디터보다 훨씬 넓은 효용"* — 프로토콜이 **비교적 중립적**이고 **에디터 전용 기능이 별로 없다** |
| **연결** | capability 집합이 딸린 클라이언트↔하네스 연결 |
| **세션** | 세션 안에서 사용자 메시지 송신, 에이전트의 텍스트·이미지·오디오 응답 |
| **알림** | **도구 호출 알림**(어떤 도구가 호출됐고 메타데이터가 무엇인지) |
| **권한** | **권한 요청** — 클라이언트가 *"이 도구 호출을 할까요?"* 를 사용자에게 보여줘야 할 때 |
| **전송** | JSON-RPC. stdio + **HTTP/WebSocket 원격**(*"지금 막 도입 중"*) |
| **확장** | 밑줄(`_`) 접두 **커스텀 메서드** |

확장 규칙이 이 소스의 가장 독특한 주장이다 — **표준화의 순서를 뒤집는다**:

> **충분히 많은 하네스 프로젝트나 클라이언트 프로젝트가 이걸 채택하면, 우리가 다 같이 똑같이 하고 있는 게 뭔지 보이기 시작**합니다. (…) **생태계에서 무엇이 떠오르는지, 무엇을 표준화 궤도에 올려 프로토콜 자체에 들여올 만한지** 볼 수 있습니다. 즉 **사용이 표준을 형성**합니다. (05:25~05:53)

## 네 구성 요소 — 에이전트 스택의 분해

발표의 아키텍처적 핵심이다.

> **클라이언트**(사용자가 쓰는 앱 또는 헤드리스 앱) · **하네스**(도구 호출 루프를 구현하는 프로그램) · **도구**(흔히 MCP) · **모델** (07:31~07:53)

> **ACP에 원격 전송이 생기고**, MCP에는 도구 호출용 원격 전송이 있고, 모델은 오래전부터 원격 엔드포인트를 가지고 있었습니다. 이제 **이 네 구성 요소를 전부 자유롭게 옮길 수 있습니다.** (07:53~08:20)

→ [[agentic-stack-decomposition]]

이 분해는 **하네스를 배포 단위로 승격**시킨다 — 하네스가 클라이언트와 다른 기계에 있을 수 있다는 말은, 이 위키가 [[cloud-agent-delegation]]에서 다뤄 온 *클라우드 에이전트* 를 **프로토콜 수준에서 일반화**한 것이다.

## 결론 — 클라이언트 카테고리와 UX 경쟁

> **여기에 새로운 카테고리를 만들면 클라이언트의 품질이 올라갈 것**이라고 봅니다. **생태계나 마켓플레이스가 생기고 선택지가 많아지면, 클라이언트가 자기 요구를 못 맞출 때 사용자는 발로 투표**하니까요. 그러면 사람들이 **사용자 경험의 품질을 놓고 경쟁**하기 시작합니다. (09:58~10:20)

## 위키의 다른 페이지와 맞닿는 자리

- **[[model-context-protocol]]** — 이 소스는 MCP를 **성공한 선례이자 자기 논증의 근거**로 쓴다. MCP 페이지에 *"힘은 규격이 아니라 보편 채택에 있다"* 는 축을 더한다.
- **[[agent-harness-design]]** · **[[harness-engineering]]** — 하네스를 *도구 호출 루프를 구현하는 프로그램* 으로 **한 줄로 정의**하고, 그것을 **교체·이전 가능한 구성 요소**로 놓는다.
- **[[cloud-agent-delegation]]** — *"에이전트는 클라우드에서 돌게 될 테니 원격이 돼야 한다"*(07:08~07:11)가 그 페이지의 전제를 프로토콜 쪽에서 받는다.
- **[[openclaw]]** · **[[agent-skills]]** — *사용이 표준을 형성한다* 는 논리는 스킬 생태계에서 이미 관찰된 것과 같은 모양이다.
- **[[tech-bridge-build-time-vs-runtime-tools]]** — ⚠️ **정면으로 비어 있는 자리.** 그 소스가 런타임 도구의 **세 신원**과 [[confused-deputy-attack|혼동된 대리인]]을 제기했는데, 이 소스는 **원격 전송을 명세했다면서 인증·인가를 한 마디도 하지 않는다.** [[lethal-trifecta]]가 정확히 이 조합(원격 + 도구 + 권한 요청)을 가리킨다.
- **[[tech-bridge-mousepower-measuring-agents]]** — 같은 날 업로드. 둘 다 컨퍼런스 발표지만 **같은 행사로 확정하지 않는다.**

## 해소하지 않고 표시만 한 것

- **경쟁 표준·대안 부재.** *"좋은 표준이 없다"* 고만 하고 기존 시도를 검토하지 않는다.
- **채택 수치 전무.** *"이미 여러 클라이언트와 에이전트 서버가 나와 있다"* 의 숫자·이름·링크가 자막에 없다.
- **원격의 보안 모델 전무** — 인증·인가·신원·격리 없음.
- **`_` 커스텀 메서드의 충돌 처리와 표준화 거버넌스** 없음.
- **Linux Foundation 기증의 거버넌스 구조** 없음.
- **MCP의 tasks 기능** — 오프닝에서 언급만 되고 설명 없음.
- **"Title"** → Tidal 추정, 확정하지 않음. **데모의 실제 결과** — 화면 의존이라 검증 불가.
- **행사·촬영 시점** — 미확정.
