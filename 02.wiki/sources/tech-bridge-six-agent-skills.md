# Tech Bridge — 바이브 코딩 생산성을 10배 끌어올리는 역대급 Claude 스킬 6가지

[[tech-bridge|Tech Bridge]]가 한영자막을 입힌 13:08 영상. 원 제작자는 [[ai-labs|AI Labs]]다(*"We're a software company and this is AI labs"*, 00:37). → [[2026-09-04_바이브 코딩 생산성을 10배 끌어올리는 역대급 Claude 스킬 6가지입니다|raw 캡처]]

이 소스의 값은 스킬 목록 자체가 아니라 **스킬을 무엇에 쓰는가의 범위가 넓어진 것**이다. 위키의 기존 [[agent-skills]] 소스들([[tech-bridge-ai-native-skills]]·[[tech-bridge-flutter-ai-workflow]])은 전부 **기술 지식**을 스킬에 담았다. 여기서는 처음으로 ① 스킬이 **자기 자신을 고치고**(task-observer), ② **제품·시장 지식**(온보딩·페이월·churn·검증)이 스킬에 담긴다.

전제부터 다른 소스와 다르다.

> 이러한 기술들은 여러분이 현재 일하는 방식을 **대체하지 않습니다.** (…) 대신, 이전에는 가능하다고 생각하지 못했던 **새로운 기능**을 추가해 줄 것입니다.

## ① task-observer — 스킬이 실패에서 자란다

진단이 이 소스의 가장 이식성 높은 문장이다.

> **가장 큰 문제는 스킬을 만드는 것 자체가 아닙니다. 최신 상태로 유지하는 것입니다.**
>
> **한 번 앉아서 에이전트가 저지를 모든 실수를 예측할 수는 없습니다.**

그래서 실제 작업 중에 교훈을 감시하고 두 곳에 적는다 — `log.md`(스킬별 제안), 그리고 **모든 스킬에 걸리는 규칙** 파일(*"어떤 스킬도 실제 고객의 이름을 파일에 기록해서는 안 된다"*).

**결정적 설계는 자동 반영을 하지 않는 것이다.**

> 로그에 기록된 내용은 (…) **검토한 후** 영구적으로 반영할지 결정할 수 있습니다. 이렇게 하면 **하나의 잘못된 결과가 에이전트가 영원히 따르는 규칙으로 자동 설정되는 것을 방지**할 수 있습니다.

→ [[skill-self-improvement]]

실제 사례(Logo Hub SVG 도구 오용)에서 나온 교훈은 두 종류다 — **금지**(이 도구를 여기 쓰지 마라)와 **대체**(올바른 출처는 이것이다). 금지만 쌓이는 규칙 집합과 다른 지점이다.

## ② Corey Haines 마케팅 스킬 3종 — 제품 지식을 스킬에 넣는다

[[corey-haines|Corey Haines]]의 마케팅 스킬 **48종** 중 앱에 직접 박히는 3종: **온보딩 · 페이월 · churn**.

이 소스에서 가장 날카로운 관찰은 왜 이것이 스킬이어야 하는지다.

> 이런 패턴은 다른 앱에서도 많이 보셨을 겁니다. 하지만 **에이전트에게 페이월 추가를 요청하면, 일반적으로 이런 선택을 하지 않습니다. 그 원칙이 내재되어 있지 않기 때문입니다.**

즉 에이전트는 *동작하는* 페이월은 만들지만 *전환되는* 페이월은 만들지 않는다. 결과물의 예:

| 스킬 | 데모에서 나온 결정 |
|---|---|
| 온보딩 | **5단계·5문항 → 1문항**(헬스장 위치). 이름은 기존 카드에서 자동 채움. 가장 인기 요금제 선택 상태로 시작. 제거한 단계는 사라지지 않고 **하단 진행률 표시줄**로 이동 |
| 페이월 | 무료 가입 → **잠긴 콘텐츠를 보여주고** → 가격 페이지로 |
| churn | 즉시 해지 금지 → **이유를 먼저 묻고** → 답변 기반 제안. **일시 중지가 주 버튼**, 취소는 그 아래 평문 |

⚠️ *"수년간의 테스트를 통해 실제 제품에서 사람들이 어떻게 행동했는지에 대한 데이터"* 를 근거로 든다. **어떤 테스트인지는 소스에 없다.**

스킬의 존재 이유도 재정의된다 — 데모의 Supabase 스킬을 두고 *"Supabase는 지속적으로 업데이트되므로 **모델 학습 내용이 사용 중인 버전과 항상 일치하지는 않습니다.**"*

## ③ Karpathy 4원칙 — 이 위키가 이미 가진 소스와 만난다

> ⚠️ **이 스킬은 [[multica-karpathy-skills-claude-md]]로 2026-05-25에 이미 ingest돼 있다.** 설명란이 링크한 repo가 같은 `multica-ai/andrej-karpathy-skills`이고, 네 규칙이 [[llm-coding-guidelines]]의 4원칙과 1:1로 대응한다. 4개월 만에 **독립적인 재발견**이 들어온 셈이고, 이 위키에서 소스 두 개가 같은 아티팩트에 도달한 첫 사례다.

| 영상의 규칙 | 위키의 기존 이름 |
|---|---|
| 불명확할 때 추측 금지 → 가정 밝히고 질문 | Think Before Coding |
| 요청보다 많이 만들지 않기 | Simplicity First |
| 준 작업 밖을 건드리지 않기 | [[surgical-edits]] |
| 뭔가 바뀌었다고 완료 선언 금지 → 검사 통과까지 | [[verifiable-goals]] |

**새로운 것은 배포 방법이다.** 스킬로 설치하지 않고 **상위 디렉터리의 `CLAUDE.md`** 에 넣는다.

> Claude Code는 프로젝트 내의 `CLAUDE.md`와 **그 상위 폴더에 있는 모든 `CLAUDE.md`를 읽습니다.**

이 배치의 요점은 범위다 — 전역(`~/.claude`)이면 무관한 세션까지 오염되고 프로젝트별이면 매번 복사해야 한다. **개발자 폴더 하나를 스코프로 만드는 중간 층**이다. → [[llm-coding-guidelines]]

문제 진단도 이 위키의 다른 소스들과 겹친다.

> **문제의 대부분은 코드 자체에서 발생하지 않습니다. 에이전트가 사용자가 요청하지 않은 결정을 내린 결과입니다.**

## ④ OpenCLI — 브라우저 대신 로그인 세션

> 브라우저 에이전트는 모든 페이지를 열고, 올바른 버튼을 찾고, **사이트를 천천히 탐색**해야 합니다.

세 부분 구조 — CLI 본체(100+ 사이트의 작업을 **한 명령 = 한 기능**으로), Chrome 확장(*"비밀번호를 다시 입력하지 않고도 계정을 사용"*), 그리고 스킬(명령 찾기 · **새 명령 만들기** · **사이트가 바뀌면 고치기**).

X를 예로 든 이유가 경제적이다 — 공식 API는 유료지만 이미 로그인된 세션으로는 검색·북마크·게시·답글·팔로우가 된다.

발표자가 스스로 경계를 긋는다 — *"**다른 사람에게 판매하는 앱에 포함된 공식 도구를 대체하기 위한 것이 아닙니다.**"* ⚠️ 로그인 세션 재사용은 서비스 약관·계정 보안 측면의 판단이 필요한 영역이고, 소스는 그 논점을 다루지 않는다.

## ⑤ Variate — 디자인 시안을 부분 단위로

> **AI 모델은 같은 디자인을 반복하는 경향이 있다.**

Variate는 앱 안에 메뉴를 붙여 **부분별 변형**을 전환·비교하게 하고, **선택이 에이전트로 되돌아간다** — *"매번 랜딩 페이지 전체를 다시 디자인할 필요가 없다."* [[tech-bridge-multimodal-commerce-agent]]의 **시각적 선호 보드**와 같은 발상(말하게 하지 말고 고르게 한다)이 개발자 도구 쪽에서 나온 사례다.

## ⑥ 미니멀리스트 엔트러프러너 — 만들기 전의 게이트

> 지금까지 다룬 모든 스킬은 에이전트가 더 나은 제품을 만드는 데 도움이 되지만, **아무도 원하지 않는 제품을 만든다면 아무 소용이 없습니다.**

[[sahil-lavingia|Sahil Lavingia]](Gumroad 창업)의 책을 **10개 스킬**로 옮긴 것. 첫 스킬은 방향을 뒤집는다 — 아이디어가 아니라 **자기가 이미 속한 그룹**에서 시작해 *"끊임없이 불평하는 문제"* 를 찾고, 그 그룹이 **광고 없이 도달 가능한지 · 이미 돈을 쓰고 있는지**를 검사한다.

두 번째 스킬이 이 소스에서 가장 구체적인 게이트다.

> **"기업" 같은 포괄적인 답변은 받아들이지 않습니다. 이름을 밝힐 수 있는 실제 인물 10명**을 요구하며, 그중 **최소 3명이 돈을 지불하겠다고 말해야** 합니다.

**10명/3명은 이 위키 전체에서 처음 나오는 "코드를 쓰기 전 통과해야 할 수치 기준"이다.** 기존의 게이트는 전부 산출물 검증([[verifiable-goals]]·[[generator-evaluator-pattern]])이었고 착수 여부를 막는 게이트는 없었다.
