# Tech Bridge — 저는 이제 Orca만 씁니다 (Rob Shocks 리뷰를 공식 기록과 대조)

[[tech-bridge|Tech Bridge]]의 **9:24 한국어 해설, 공식 챕터 9.** 에이전트 개발 환경을 거의 다 써 봤다는 리뷰어 [[rob-shocks|Rob Shocks]]가 [[claude-code|Claude Code]]를 돌리는 기본 도구를 [[orca|Orca]]로 바꿨다는 리뷰 영상을, **GitHub 저장소 · 릴리스 노트 · README · orca.dev 문서와 하나씩 맞춰 본다.** 설명란: *"리뷰와 기록이 다른 곳은 기록을 따르고 차이를 화면에 밝혔습니다."* raw: `01.raw/articles/2026-11-17_저는 이제 Orca만 씁니다 에이전트 IDE 다 써 본 리뷰어가 갈아탄 이유.md`.

> *"우리는 매일 배포한다. 그래서 이 기능 목록은 늘 뒤쳐져 있다. 진짜 기능 목록은 변경 기록이다."*(00:03~00:07) — Orca 소개 글의 문장(해설 인용)

## 1. 진짜 기능 목록은 변경 기록이다 (00:00~00:59)

- 근거로 든 기록: *"저장소가 생긴 지 여덟 달, 시험판과 모바일 앱까지 합쳐 릴리스가 1012개 올라왔습니다."*(00:09~00:15) GitHub 별은 12만 5천 개를 넘었다.
- 계기: *"그리고 지난주 에이전트 개발 환경을 거의 다 써봤다는 리뷰어가 이 도구로 갈아탔다고 밝혔습니다."*(00:21~00:25)
- 질문: *"두 달 전에는 모자랐던 도구가 왜 지금은 기본값이 됐을까요?"*(00:49~00:51) — ⚠️ *두 달 전에는 모자랐다* 는 평가의 원문은 무캡션 구간(00:28~00:49)에 있다.

## 2. Orca의 정체: 에이전트와 구독은 그대로 (00:59~02:02)

- 리뷰어 소개: *"리뷰한 사람은 롭 쇼크스입니다. 에이전트 개발 환경을 두루 써보고 영상으로 남겨온 유튜버입니다."*(00:59~01:02)
- 화면: 왼쪽에 프로젝트 목록, 가운데에 터미널.
- 무엇이 아닌가: *"오르카는 새로운 AI 모델이 아닙니다. 새로 나온 코딩 에이전트도 아닙니다."*(01:09~01:13) Claude Code나 [[codex|Codex]] 같은 에이전트를 여러 개 띄워 놓고 한곳에서 굴리는 **작업대** 다. → [[agent-development-environment]]
- 소개 글의 표현: *"터미널에서 돌아가는 에이전트라면 오르카에서도 돌아간다."*(01:20~01:21)
- 요금: *"오르카가 모델을 대신 불러주는 게 아닙니다."*(01:46~01:47) 내 컴퓨터에 이미 깔린 Claude Code를 그대로 실행한다. *"그래서 요금도 오르카가 아니라 원래 쓰던 구독에서 나갑니다."*(01:52~01:54) 기업용 소개 페이지: *"오르카는 중간에 끼지 않는다."*(01:58~02:00) → [[bring-your-own-subscription]]

## 3. 채팅 모드, 정말 새 기능일까 (02:02~03:05)

- 공식 문서의 설명: *"채팅 화면은 에이전트 세션을 보는 방식 가운데 하나다."*(02:34~02:36) 에이전트가 바뀌는 게 아니라 같은 Claude Code를 터미널로 보느냐 채팅으로 보느냐의 차이.
- ⭐ **리뷰 vs 기록 ①**: Shocks는 새로 나온 기능이라 했지만 *"릴리스 기록에는 6월 말부터 채팅 화면이 나옵니다."*(02:46~02:48) 다만 11월 4일 릴리스부터 처음 설치할 때 채팅과 터미널 중에 고르게 됐다. 해설의 해석: *"그가 말한 지난 한 두 주의 변화는 이런 다듬기가 쌓인 결과로 보입니다."*(02:55~02:57)
- 기본값은 지금도 터미널 — 채팅을 고르지 않으면 터미널로 열린다.

## 4. 에이전트 하나에 워크트리 하나 (03:05~04:14)

- 워크트리: *"저장소 하나에서 작업 폴더를 여러 개 꺼내 쓰는 깃의 기능입니다."*(03:08~03:10)
- 왜: *"에이전트 셋이 한 폴더에서 동시에 파일을 고치면 서로의 작업을 덮어쓰게 됩니다."*(03:13~03:16) 폴더를 따로 주면 각자 자기 브랜치에서 일하고 끝난 것만 합친다. (03:23~04:00 무캡션)
- 할 일 목록 연동: GitHub 이슈 · Jira · Linear 항목에서 시작 버튼을 누르면 그 일을 맡을 워크트리가 바로 만들어진다.
- 에이전트가 늘면 보드로 — 할 일 · 진행 중 · 리뷰 중 · 완료의 칸반.

## 5. 내장 브라우저: 표시해서 전달, 확장과 비밀번호 (04:14~05:16)

- 에이전트가 만든 화면을 Orca 안에서 연다. *"고칠 곳에 직접 표시를 하고 메모를 달면 그 표시들이 한 묶음으로 에이전트에게 전달됩니다."*(04:19~04:23) *"말로 설명하기 애매한 디자인 수정을 손가락으로 짚어 주는 셈입니다."*(04:25~04:27)
- ⭐ **리뷰 vs 기록 ②**(일치): *"이 대목은 릴리스 기록과 날짜가 맞습니다."*(05:01~05:03) Chrome 호환 비밀번호 관리 기능은 11월 5일 릴리스, 확장 프로그램은 11월 13일 릴리스부터 기본으로 켜졌다 — *리뷰 영상이 올라오기 하루 전*(→ 리뷰 영상은 11월 14일, 위키 계산). ⚠️ 리뷰가 이 대목에서 무엇을 말했는지는 무캡션(04:30~05:01).

## 6. 원격 서버와 지연 (05:16~06:26)

- 에이전트를 내 노트북이 아니라 빌린 서버에서 돌린다 — 노트북을 덮어도 계속 일한다. 대신 지연이 생긴다. → [[cloud-agent-delegation]]
- 원리: *"원격 터미널에서는 글자 하나를 칠 때마다 그 글자가 서버까지 갔다 와야 화면에 찍힙니다."*(05:55~05:59) *"채팅 화면은 입력 창이 내 컴퓨터에 있습니다. 다 쓰고 보낼 때만 서버로 갑니다."*(06:00~06:04)
- ⭐ **리뷰 vs 기록 ③**: *"쇼크스의 말처럼 지연이 사라진 건 아닙니다. 타자를 칠 때 느껴지지 않을 뿐입니다."*(06:05~06:08) 그리고 단서: *"문서에는 SSH 세션은 터미널 기반 채팅을 쓴다고 적혀 있습니다."*(06:11~06:13)
- 모바일: *"모바일 앱은 내 컴퓨터의 오르카를 조종하는 리모컨입니다."*(06:17~06:21) 에이전트가 사람을 찾으면 알림이 오고 밖에서 답을 보내 일을 이어 간다. → [[agent-attention-management]]

## 8. 오픈 소스면 안심일까 (07:20~08:24)

- 근거가 있는 쪽: MIT 라이선스 — 누구나 가져가 고쳐 쓸 수 있고 *"회사가 방향을 틀어도 그 시점까지의 코드는 남습니다."*(07:47~07:48)
- 단서: *"다만 만드는 곳은 회사입니다."*(07:50) [[stably-ai|Stably AI]] — Y Combinator의 투자를 받은 곳. 앱은 무료지만 계정에 로그인해야 쓰는 기능이 있다(모바일 연결 · 공유 링크).
- 사용 통계 — 공식 문서의 문장: *"이 식별자는 익명이 아니라 가명이다."*(08:06~08:08) 같은 설치에서 나온 기록끼리는 엮을 수 있다는 뜻(08:09, ASR *엿볼* — 판독 추정). 문서에 따르면 파일 내용 · 프롬프트 · 에이전트 응답은 수집하지 않도록 설계했고 설정에서 끌 수 있다.
- 해설의 권고: *"오픈 소스니까 괜찮겠지 하고 넘기기 보다 이런 문서를 한번 읽어 보는 편이 낫습니다."*(08:18~08:22)

## 9. 정리와 감안할 점 (08:24~09:24)

- 남는 것 셋: *"하나, 에이전트와 구독은 그대로 두고 그 바깥의 작업대만 바꾼다."*(08:45~08:49) *"둘, 에이전트 하나에 워크트리 하나."*(08:51) 셋, 화면은 채팅이든 터미널이든 골라서 본다.
- 감안 셋: *"플러그인은 아직 알파이고 열린 이슈가 수천 개이며 도구가 거의 매일 바뀝니다."*(08:58~09:02)
- 자기 유보: *"그래서 이 영상도 금방 낡을 겁니다."*(09:06) 써 볼 사람에게는 기능 소개보다 최근 릴리스 노트 몇 개를 먼저 읽으라고 권한다.

## 위키의 읽기

- ⭐ **이 채널의 *기록과 대조* 형식이 제품 리뷰로 옮겨 왔다.** 11-13 *GPT-6 Cyber 키노트를 기록과 대조* 가 벤더 발표를 상대로 했던 일을, 이번에는 제3자 리뷰어를 상대로 한다. 결과는 셋 — 틀림(채팅 모드는 6월 말부터 있었다) · 맞음(브라우저 확장 · 비밀번호의 날짜) · 표현 교정(지연은 사라진 게 아니라 안 느껴질 뿐). 다만 **리뷰어의 원문이 전부 무캡션** 이라 위키에서는 대조의 한쪽(기록 쪽 내레이션)만 보인다.
- ⭐ **같은 범주의 여섯 번째 도구, 그리고 처음으로 *기록* 이 붙은 도구.** [[conductor]] · [[agentcraft]] · [[warp]]는 만든 쪽의 발표로, [[herdr]] · [[cmux]]는 한 사용자의 몇 시간 사용기로 들어왔다. Orca는 제3자 리뷰 + 저장소 통계 + 문서 인용으로 들어온 첫 사례이고, 텔레메트리 정책 · 릴리스 속도 · 열린 이슈 수가 적힌 첫 사례다(오픈 소스로는 [[warp]]에 이어 둘째). → [[agent-development-environment]](신규)
- **워크트리를 둘러싼 두 방향이 같은 주에 나란히 있다.** 11-14 Lauren Tan 편의 *워크트리는 끝났다, 클라우드 에이전트가 미래다*, 11-17 Ryan Carson의 *로컬 개발은 돌 두드리기* ([[cloud-agent-delegation]]) vs 이 편의 *에이전트 하나에 워크트리 하나*. Orca는 둘을 한 앱에 넣었다 — 로컬은 워크트리, 원격은 빌린 서버. [[conductor]]가 워크트리에서 클라우드 샌드박스로 **옮겨 간** 것과 달리 **둘 다 둔다.** ⚠️ 원격에서도 워크트리를 쓰는지는 말하지 않는다.
- **채팅 화면이 지연 문제의 답이 된다** 는 설명은 위키에 처음이다 — 입력을 로컬에서 끝내고 한 번에 보낸다. [[herdr]] 페이지에는 원격 worker의 장점(세션이 살아남는다)만 있고 타자 지연 이야기는 없다.
- **BYO 구독의 도구 쪽 사례.** [[bring-your-own-subscription]]은 앱 개발자가 사용자의 ChatGPT 구독에 올라타는 이야기였고 반대 사건(서드파티 에이전트의 구독 사용 차단)도 적혀 있다. Orca는 모델을 대신 부르지 않고 **사용자의 CLI를 그대로 실행** 하는 방식이라 그 차단의 대상과는 구조가 다르다(위키 해석 — 벤더 약관상 어떻게 다뤄지는지는 이 소스가 말하지 않는다).
- **Rob Shocks의 이름이 처음으로 발화된다.** 11-03 편에서는 설명란에만 있었다([[rob-shocks]]). 이번에는 내레이션(00:59) · 설명란 · tags · 원본 링크가 모두 있다.
- ⚠️ 영어 더빙이 리뷰어 이름을 *Rob Shouksmith* 로 읽는다 — 더빙을 근거로 삼지 않는 이유 하나.
- 페이지화하지 않음: git worktree(기능 자체) · Y Combinator · Jira · Linear · Orca 모바일 앱 · Orca 플러그인(알파).
