# Tech Bridge — 사람은 위험한 명령의 14%만 잡았다 (Rethinking Claude Code Best Practices 정리)

[[tech-bridge|Tech Bridge]]의 **8:48 한국어 해설, 공식 챕터 10.** [[anthropic|Anthropic]] [[claude-code|Claude Code]] 팀 [[lydia-hallie|Lydia Hallie]]가 AI Engineer Code Summit에서 한 발표 *"Rethinking Claude Code Best Practices"* 를 따라간다(설명란). 축은 **사람이 루프에서 하던 다섯 가지 일 — 조종 · 승인 · 거절 · 확인 · 시작 — 이 각각 무엇으로 옮겨 갔나** 다 → [[human-loop-roles-relocation]](신규). 내레이션은 AI 음성이다(설명란). 발표 원음으로 보이는 발췌는 **무캡션**이다(en-orig 없음). raw: `01.raw/articles/2026-11-12_사람은 위험한 명령의 14%만 잡았다 Anthropic Claude Code 팀이 다시 쓴 모범 사례 8분 정리.md`.

테제(맺음):

> *"예전 모범 사례는 사라진게 아니라 자리를 옮겼습니다."*(08:01~08:05)

> ⚠️ **발표와 수치는 해설자의 번역 · 요약이다.** 실험 수치 · 머지 수 · 공식 문서 문장은 한국어 내레이션으로 옮겨진 것이고 위키는 원 발표 · 링크(auto mode 기본값 블로그, source control 재설계 글, best practices · sandboxing · hooks 문서)를 열지 않았다. 리디아 본인의 말로 보이는 발췌(다섯 곳 이상)는 ko-orig에 캡션이 없어 **내용 미상**이다.
>
> **트랙과 인용.** 오디오는 `ko` 하나. `ko` = `ko-orig`(md5 동일, `kind=asr&lang=ko`)가 원 ASR이고 `en`은 그 기계 번역이다. 인용은 전부 ko-orig다. ASR이 `.env`를 *엠브 · 다 램부 · 다 엠부* 로, CI · PR을 *C · 피 · 피아* 로, 훅을 *후* 로 적는다. 판독 목록은 raw 헤더에 있다.

## 1. 사람은 14%만 잡았다 (00:00~00:39)

- Anthropic이 8월에 공개한 실험: 테스터 1,053명의 코딩 세션마다 위험한 명령을 하나씩 몰래 끼워 넣었다(00:00~00:07). *"사람이 잡아낸 건 약 14%였습니다."*(00:10~00:13) 같은 명령을 auto mode 분류기는 89% 막았다(00:14~00:17). 원문 수치로 1,053명 중 143명, auto mode는 937건(00:17~00:22). 설명란은 *13.6%* 로 적는다.
- ⭐ 그런데 *"열개 중 한 개는 여전히 통과했습니다."*(00:27~00:30) — 영상 전체가 그 하나를 막는 장치를 따라간다. → [[transcript-classifier]]

## 2. 올해 초의 세션, 지금의 세션 (00:39~01:23)

- 올해 초: 모델은 [[claude-opus-4-5|Opus 4.5]] — *"당시에 훌륭했지만 지금보다 훨씬 일찍 멈췄습니다."*(00:43~00:45) 사람이 계속 고쳐 줬고(*테스트 말고 코드를 고쳐라 · 우리 인증 헬퍼를 써라*) 명령도 하나하나 승인했다(00:47~00:55).
- 지금 Anthropic 안의 세션: 수십 개가 동시에 몇 시간씩 돌며 결과를 스스로 검증한다(00:57~01:01). 01:04~01:13 무캡션 발췌 뒤 성과: *"5월에 하루 평균 2,500권쯤 머지되던 코드 변경이 9월에는 3만권에 넘었습니다."*(01:13~01:19)[=2,500건 · 3만 건] → [[tech-bridge-anthropic-30k-merges-verification]]의 *하루 3만 건* 과 같은 숫자다.

## 3. 사람이 하던 다섯 가지 일 (01:23~01:43)

- 리디아는 예전 모범 사례를 다섯 가지 일로 정리한다 — *"방향을 잡아주고 명령을 승인하고 안 된다고 막고 결과를 확인하고 세션을 시작하는 일."*(01:25~01:30)
- *"후보는 셋입니다. 모델, 하네스, 그리고 모델이 돌아가는 환경."*(01:36~01:38) → [[human-loop-roles-relocation]]

| 사람의 일 | 옮겨 간 곳 | 영상 |
|---|---|---|
| 조종(steer) | 모델 — Opus 5.5 · CLAUDE.md 정리 | §4 |
| 승인(approve) | auto mode 분류기 + 신뢰 대상 설정 | §5 |
| 거절(deny) | 거절 규칙(되돌릴 수 없는 것) + 샌드박스 · 클라우드 세션 | §6~7 |
| 확인(verify) | 검증 지점 · 훅(exit 2) | §8 |
| 시작(start) | CI · Claude 리뷰 · 지휘자 세션 | §9 |

## 4. 조종 → 모델: CLAUDE.md에서 지울 것 (01:43~02:40)

- [[claude-opus-5-5|Opus 5.5]]는 의도와 코드베이스를 훨씬 잘 이해해 중간에 고쳐 줄 일이 줄었다 — 그러면 지시문도 달라져야 한다(01:43~01:52). CLAUDE.md에 아직 *깊이 생각해라 · 끝날 때까지 계속해라 · 중요 · 반드시 인증 헬퍼를 써라* 같은 줄이 남아 있지 않나(01:52~02:00). 02:03~02:10 무캡션 발췌.
- 공식 문서: *"강조를 쌓으면 클로드가 그 규칙을 과하게 적용한다고요."*(02:12~02:14) 기준 — ⭐ *"클로드가 저장소를 읽어서 알 수 없는 것만 적으라는 겁니다."*(02:18~02:20) 스택 · 볼 곳은 코드에 있으니 지운다. 코드에 드러나지 않는 사실(레거시 폴더를 아직 모바일 앱이 쓴다)은 남긴다(02:21~02:31). → [[prompt-debt]]
- 직접 고르기 어려우면 모델에 맞춰 CLAUDE.md · 스킬의 지시를 찾아 수정안을 제안하는 명령어가 있다(02:31~02:39). ⚠️ 명령 이름은 ASR이 *닥터 프롬프트 오* 로 적어 판독하지 못했다.

## 5. 승인 → auto mode (02:40~03:30)

- Anthropic은 8월부터 auto mode를 세션의 기본 권한 모드로 바꾸기 시작했다(02:40~02:46). 프로젝트 안 파일 읽기 · 고치기 말고는 거의 모든 동작을 별도 분류기에 보낸다 — 테스트 실행 · 의존성 설치처럼 안전하다고 보는 명령은 통과, *"확신이 없으면 [음악] 차단입니다."*(02:56~02:58) → [[transcript-classifier]] · [[deny-and-continue]]
- 쓰다 보면 또 사람을 부른다 — 스테이징 배포를 부탁하면 막힌다. 기본값은 지금 폴더와 지금 저장소만 믿기 때문이다(03:00~03:11). 해결책은 설정 파일: *"우리가 믿는 저장소와 버킷, 도메인을 평범한 영어 문장으로 적어도 두면 그 문장이 분류 기획에 전달됩니다."*(03:14~03:18)[=분류기에]
- 여기까지는 기본값만 따라가도 조종과 승인에서 빠질 수 있다. *"어려운 질문은 이제부터입니다. 내가 없어도 괜찮다는 걸 어떻게 보장할까요?"*(03:26~03:29)

## 6. 거절 → 규칙: 되돌릴 수 있는가? (03:30~04:23)

- ⭐ *"모델에게 맡기면 대부분 잘되지만 보장은 아닙니다. 보장은 한스에서만 걸 수 있습니다."*(03:36~03:41)[=하네스] → [[hard-vs-soft-enforcement]]
- 거절은 예전 모범 사례가 그대로 살아 있는 곳이다 — 권한 설정의 거절 규칙. *"규칙에 걸린 도구출은 분류기에 아예 도착하지도 않습니다."*(03:50~03:52)[=도구 호출]
- 무엇을 규칙으로 만들까 — 리디아의 기준은 질문 하나다(03:54~03:56, 이어지는 03:56~04:04는 무캡션 · 챕터 제목은 *되돌릴 수 있는가?*). 코드를 잘못 썼다면 git으로 되돌리면 되니 모델에게 맡긴다. *"하지만 영어지는 것, 비밀값이 드러나는 것, 바깥으로 나가는 것은 되돌릴 수 없습니다. 이런 건 규칙으로 만듭니다."*(04:08~04:14)[=지워지는 것(추정)] → [[action-reversibility]]
- 예: `.env` 파일 — auto mode는 기본적으로 읽기를 허용하니, 절대 읽히고 싶지 않다면 거절 규칙 한 줄(04:14~04:22).

## 7. 샌드박스와 클라우드 세션 (04:23~05:56)

- 규칙만으로 못 막는 구멍: `npm test`는 평범해서 auto mode가 통과시키지만, 내가 쓰지 않은 의존성 코드도 함께 돈다. 그중 하나가 오염됐다면 `.env`나 SSH 키를 열어 처음 보는 서버로 보낼 수 있다(04:25~04:42). → [[prompt-injection]]
- 04:45~04:51 무캡션 뒤: *"관환 규칙은 도구 호출을 실행할지 말지만 정합니다. 일단 실행된 뒤 어디까지 손을 뻗는지는 막지 못합니다."*(04:51~04:56)[=권한 규칙] 그래서 명령이 아니라 **환경**을 제한한다 — 샌드박스. 기본으로 꺼져 있어 직접 켜야 하고, 읽을 파일 · 쓸 폴더 · 접촉할 호스트를 운영체제가 강제한다 — *"그 명령이 띄운 자식 프로세스까지 전부요."*(05:06~05:08) 거절 규칙도 운영체제로 넘어간다(05:10~05:13). → [[agent-sandboxing]]
- ⚠️ 단, *"샌드박스가 덮는 건 쉘 명령뿐입니다."*(05:16~05:17) Claude의 파일 도구 · MCP 서버 · 훅은 여전히 바깥, 내 컴퓨터에서 돈다(05:17~05:21).
- 다음 단계는 그런 것이 애초에 없는 곳 — **클라우드 세션**: 세션마다 새 머신과 저장소의 새 복사본, 노트북을 닫아도 계속 돈다. git에 없는 `.env` · SSH 키는 거기에 아예 없다. 네트워크는 기본으로 패키지 레지스트리와 GitHub 정도만 열리고, API 키는 Claude가 값을 보지 못한 채로 쓰게 할 수 있다(05:25~05:41). → [[cloud-agent-delegation]] · [[credential-injection-outside-sandbox]]
- *"머신은 버리면 되지만 푸시된 커믹과 전송된 메시지는 남습니다."*(05:49~05:51)[=커밋] — 그래서 클라우드에서도 auto mode와 거절 규칙은 그대로 둔다.

## 8. 확인 → 검증 지점, 훅, exit 2 (05:56~07:10)

- 안전해졌다면 남는 건 *일을 제대로 했느냐*. 몇 시간 뒤에 돌아와 *"바뀐 파일 63개를 전부 읽지는 않겠죠."*(06:05~06:07) 같은 프롬프트(인증을 새 API로)에도 결과가 갈린다 — 옛 API를 남기기도, 모든 사용자를 로그아웃시키기도 한다(06:10~06:16). → [[verification-bottleneck]]
- 그래서 중간중간 **검증 지점** — 통과 아니면 실패로 답이 나오는 것: 테스트 · 빌드 · 스크린샷(06:18~06:24). 가장 쉬운 건 프롬프트(완료 기준 · 작업을 나눠 각각 테스트 · 실제 출력 보여 달라). *"하지만 프롬프트는 보정이 아니죠."*(06:32~06:34)[=보장]
- 반드시 돌아야 하는 검사는 **훅**으로: 파일을 고칠 때마다 린트, 작업을 완료로 표시할 때마다 그 부분의 테스트, Claude가 멈추려 할 때 전체 테스트(06:35~06:45). → [[hook-enforced-workflow]] · [[layered-verification-every-loop]]
- ⭐ 함정(06:45~07:05 대부분 무캡션, 챕터 제목 *exit 2*): *"종류 코드가 1이면 작업은 그냥 완료 처리됩니다. 2를 돌려 줘야 클로드가 돌아가서 고칩니다."*(07:05~07:09)[=종료 코드] — 검사가 실패해도 exit 1이면 막히지 않는다.

## 9. 시작 → CI, 리뷰, 지휘자 세션 (07:10~08:02)

- 세션 하나를 믿고 맡길 수 있으니 여러 개를 띄운다 — 각자 머신이 있어 부딪히지 않는다. ⭐ *"이때 가장 중요한 건 C입니다. 세션이 어떻게 설정됐든 모든 피에 똑같은 검사가 돌기 때문입니다."*(07:15~07:22)[=CI · PR] autofix를 켜면 검사가 실패했을 때 Claude가 돌아와 고친다(07:22~07:26).
- 리디아 팀에서는 모든 PR을 Claude가 먼저 리뷰한다 — *"코드를 쓴 세션이 아니라 새 컨텍스트에서요."*(07:30~07:32) 사람이 얼마나 볼지는 위험도로 정한다: 문서 · 문구 수정은 자동 검사만, 보통 변경은 한 명, 위험한 변경은 두 명(07:32~07:40). → [[risk-proportional-human-review]] · [[automated-code-review]]
- 다섯째, 세션을 시작하는 일까지 Claude에게: 아직 베타인 기능에서 메인 세션 하나가 **지휘자** 가 된다 — 할 일을 말하면 하위 세션을 띄우고, 돌아온 결과가 덜 끝났으면 돌려보낸다(07:42~07:53). 리디아의 구성: *"판단하는 메인 세션의 페이블. 실제 작업을 하는 쓰레드의 오퍼스 5.5입니다."*(07:55~07:59) → [[fable-5-2]] · [[model-mixing-economics]]
- ⚠️ 기능 이름은 *"아직 베타인 클로드 코드 프로젝트"*(07:44~07:46)로만 들려 확정하지 못했다. *페이블* 의 버전은 발화되지 않는다(tags에 Fable 5.2).

## 10. 정리 (08:02~08:48)

- 조종은 모델이, 승인은 auto mode가, 거절은 규칙과 환경이, 확인은 테스트와 훅과 CI가, 시작은 Claude가 맡는다(08:03~08:12). 08:15~08:24 무캡션 발췌.
- *"되돌릴 수 없는 것만 규칙으로 막고 나머지는 환경과 검사에 맡기는 것이었죠."*(08:28~08:33)
- 리디아의 제안: 평소보다 훨씬 큰 일 하나를 골라 클라우드에서 돌려 보고, 세션이 어디서 멈추는지 · 내가 어디서 아직 끼어드는지 보라 — *"그게 바로 다음에 클로드에게 넘겨 줄 일입니다."*(08:43~08:45)

## 위키의 읽기

- **auto mode 소스([[anthropic-claude-code-auto-mode]])의 *후속 운영편*.** 그 글이 분류기의 설계를 말했다면, 이 발표는 **분류기가 놓치는 10%를 무엇이 받치나** 를 말한다 — 답은 *되돌릴 수 없는 것만 하드 규칙, 나머지는 환경(샌드박스 · 클라우드)과 검사(훅 · CI)*. [[hard-vs-soft-enforcement]]의 *모델에게는 대부분, 보장은 하네스에서* 와 같은 선이다.
- **[[action-reversibility]]가 권한 설계의 기준선이 된다.** 기존 소스들은 가역성을 *사람 승인을 붙일 곳* 으로 읽었는데, 여기서는 **거절 규칙을 붙일 곳** 이다 — 사람이 아니라 규칙이 되돌릴 수 없는 행동을 맡는다.
- **샌드박스의 경계가 명시된다.** *셸 명령만 덮고 파일 도구 · MCP · 훅은 바깥* 은 [[agent-sandboxing]]에 처음 기록되는 한계다(해설 전달). 그 바깥을 없애는 방법으로 클라우드 세션이 나온다.
- **CLAUDE.md 정리 기준은 [[prompt-debt]]의 세 번째 소스다.** Lance Martin(11-09) · Chase AI(11-12)에 이어 Claude Code 팀이 *강조를 쌓으면 과하게 적용* 을 말한다. 기준 문장은 *저장소를 읽어서 알 수 없는 것만 적어라* 다.
- **훅의 exit code 함정**(1은 통과, 2만 되돌림)은 [[hook-enforced-workflow]]의 실무 세부로 처음 기록된다. ⚠️ 위키는 hooks 문서를 열지 않았다.
