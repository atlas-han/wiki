## 2. 모든 코드는 슬롭이다, 내 것만 빼고 (00:38~02:14)

- 소개(해설): 온라인 이름 poteto, Meta · Netflix · Cursor를 거쳤고 React 코어 팀에서 React Compiler를 만들어 왔다. *"지금은 스페이스 엑스 AI에서 그록봇이라는 제품을 만듭니다."*(00:49~00:51) ⚠️ 설명란 표기는 `SpaceXSI Grok Bot 팀`, 영어 더빙은 `xAI`.
- 첫 슬라이드의 농담 — *"우리의 영웅적인 4,000줄짜리 PR, 저들의 야만적인 4,000줄짜리 PR."*(01:04~01:07) 똑같은 물건인데 남의 것만 슬롭으로 보인다. → [[ai-slop]]
- 에이전트 덕분에 누구나 코드를 쏟아낼 수 있으니 *"엔지니어의 일은 양을 크게 늘리면서 품질을 지키거나 더 올리는 방법을 찾는 것"*(01:35~01:39).
- *"여섯 달이 걸렸다고 합니다."*(02:10) — 무엇에 여섯 달인지는 직전 발췌(01:44~02:10) 안이라 캡션에 없다.

## 4. 코드는 기억이다 (03:10~03:54)

- 에이전트의 가장 큰 입력 가운데 하나가 코드베이스다. 10월 X 게시물: *"코드 베이스는 기억이다."*(03:19~03:21)
- 2024년에는 출근해서 동료 PR 세 개를 리뷰했고 *"지금 그 숫자는 300개에 가깝다고 합니다."*(03:28~03:30) 엔지니어 한 명이 에이전트 수백 · 수천을 거느린 팀이 됐고 코드는 끊이지 않는 물줄기처럼 들어온다 → 정원 가꾸기.
- 잡초는 코드에 남은 임시방편 — 다음 에이전트는 그걸 저장소의 관례로 읽고 베낀다. 슬라이드 문장: *"한 번 베낄 때마다 다음에 또 베낄 가능성이 커집니다."*(03:50~03:52) → [[codebase-gardening]]

## 6. 주석은 부채다 (04:49~05:54)

- *"그래서 그록봇 팀은 주석의 99%를 금지하기로 합니다."*(04:50~04:52) 슬라이드: 7월 31일 65,824 → 발표 시점 1,227.
- 대신 들어간 건 린트 규칙 — 타이머를 쓰면 검사가 막고, *"오류 메시지에는 에이전트가 읽을 지시가 적혀 있습니다. 덮지 말고 근본 원인을 고치라는 겁니다."*(05:36~05:41)
- [[pstack]]의 no-comment 스킬(이름 판독)이 주석을 걷어낸다. *"주석이 말하던 제약이 진짜라면 주석이 아니라 타입이나 검사로 옮겨 적으라는 겁니다."*(05:49~05:53) → [[comments]]

## 7. 애매하면 금지한다 (05:54~07:24)

- [[dune-architecture|Dune]] — [[grokbot|GrokBot]] 팀이 만든 프레임워크, Lauren의 표현으로 Electron 앱을 위한 Next.js 같은 것. 교훈: 잘 쓰려면 미묘한 판단이 필요한 것은 슬롭으로 이어진다(06:02~06:06, ASR *슬로우* — 판독 추정).
- *"제품 코드에서는 아예 못 쓰게 했고 뷰 안쪽 몇 군데에서만 허용했습니다."*(06:33~06:35) — 목적어는 직전 발췌 안이다(tags의 `useEffect`로 추정). *"리뷰에서 이걸 잡아낼 일 자체가 없어졌습니다."*(06:37~06:39)
- 폴더 구조도 규칙 — Electron 렌더러 / 메인, 최상위 폴더 이름이 그대로 경계이고 둘 사이의 import는 의존성 분석기와 린트가 막는다. 메인 스레드 코드를 렌더러로 끌어와 화면이 버벅이던 Cursor 시절의 실수를 구조로 막았다.
- 검사는 쌓인다 — 슬라이드의 계단 그래프는 *"7월에 7에서 시작해 11월에 167까지 올라갑니다."*(06:58~07:03) 단위는 말하지 않았고 그래프 제목은 *에이전트를 바로잡을 때마다*.

## 8. 토큰의 70%는 검증에 (07:24~08:37)

- 보는 대상이 바뀌었다 — *"코드 대신 검증 결과물을 봅니다. 영상, 스크린샷, 다이어그램입니다."*(07:28~07:30) → [[agent-change-evidence]]
- 기본은 런타임 검증(에이전트가 앱을 직접 실행하고 사람이 쓰는 디버깅 도구를 그대로 쓴다) + [[feature-map|기능 지도]] — *왼쪽 사이드바의 그거* 라고만 해도 헤매지 않는다. → [[agent-verification-skill]]
- 최근에는 형식 검증 — 여러 기기에 걸친 알림 같은 주요 흐름은 TLA+로 모델 검사, 직접 만든 가상화 라이브러리의 알고리즘은 Lean으로 증명(화면이 깜빡이거나 떨리지 않는지). 버그를 꽤 찾았지만 *"아직 실험 중이라고 선을 긋습니다"*(08:03~08:05). → [[ai-formal-verification]]
- Cindy Sridharan의 글 두 개(해설의 번역 전달). 5월: AI가 만든 PR 여러 개가 미묘한 버그를 안고 머지됐고 고치는 데 며칠이 더 들었다. 여섯 달 뒤: 그때 없던 건 검증 과정이었다 — *"지금은 하루 토큰의 70%가 패치를 검증하는 데 들어간다."*(08:24~08:26)
- Lauren도 자기 토큰 대부분이 검증에 들어간다고 한다. *"새로운 기법은 없습니다. 예전에는 비싸서 못 하던 테스트를 에이전트가 싸게 만들어 준 겁니다."*(08:31~08:35) → [[verification-cost-asymmetry]]

## 위키의 읽기

- ⭐ **피라미드에 *검증* 층이 생겼다.** 09-26 본인 발표는 다섯 층(코드베이스 · 정적 분석 · 규칙과 bugbot · 스킬 · 스타일 가이드), 11-03 Rob Shocks 요약은 네 층(… prose · 사람 리뷰)이었다. 이번 판은 **코드베이스 · 정적 분석 · 검증 · 글로 쓴 지시 · 사람 리뷰** — 규칙과 스킬이 *글로 쓴 지시* 한 층으로 합쳐지고 그 위에 **검증** 이 독립된 층으로 들어갔다. *결정적* 이라고 부른 것은 여전히 위 두 층뿐이다. 층 이름은 발표마다 조금씩 다르고, 위키는 어느 판도 정본으로 삼지 않는다. → [[hard-vs-soft-enforcement]]
- ⭐ **주석 금지의 근거가 일화에서 사건 기록으로 바뀌었다.** 11-14 요약은 *주석은 잡초* 라는 비유와 *"Lauren이 절대 이렇게 하지 말랬음"* 같은 예시였다. 여기서는 날짜가 붙은 전파 기록(9월 9일 한 줄 → 10월 17일 183개)과 원인 분석(주석이 임시방편을 *괜찮다고 설명* 했다)이 붙는다. [[comments]](Refactoring Guru의 코드 스멜)가 *사람이 읽는 코드* 에서 말하던 것과 결론은 같고 이유가 다르다 — 사람에게 주석은 낡는 설명이고, 에이전트에게 주석은 **베껴도 된다는 허가** 다.
- **성적표에 빨간 숫자가 같이 실렸다.** 대기 중 CPU 100% 증가 · 메모리 12% 증가를 해설이 빼지 않고 전한다. 되돌린 커밋 비율은 품질의 한 면일 뿐이고(되돌리지 않은 나쁜 코드는 잡히지 않는다), 타이머 사건이 바로 *되돌려지지 않고 퍼진* 성능 문제였다는 점에서 이 표의 빨간 줄과 같은 종류다(위키의 관찰).
- **dark factory에 대한 입장.** 10-10 풀버전 대담에서는 *다크 팩토리* 라는 말에 *"It kind of is"* 라고 받았는데, 이번 해설은 본인 게시물 *not a dark factory* 를 인용한다. 게시물 원문 · 시점을 열지 않았으므로 입장이 바뀐 것인지 맥락이 다른 것인지 판단하지 않는다. → [[software-factory]]
