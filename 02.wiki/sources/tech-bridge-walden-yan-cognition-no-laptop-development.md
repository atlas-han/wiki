# Tech Bridge — 노트북을 열지 않고 개발하는 회사 (Walden Yan)

[[tech-bridge|Tech Bridge]]의 **10:32 한국어 해설, 공식 챕터 12.** 코딩 에이전트 [[devin|Devin]]을 만드는 [[cognition|Cognition]]의 공동 창업자 [[walden-yan|Walden Yan]]이 AI Engineer Code Summit(11월 12일, 샌프란시스코)에서 한 발표를 슬라이드와 글로 남은 기록에 맞춰 따라간다. 머지된 PR이 1년 사이 40배가 되는 동안 엔지니어는 2.7배 늘었다는 그래프에서 출발해, 그 사이에 바꾼 것 — 사람의 역할, 에이전트가 혼자 시험해 볼 수 있는 환경, 일감 대신 목표를 맡기는 방식 — 을 차례로 본다. 끝에는 이 발표가 신제품 [[devin-bots|Devin Bots]]의 예고편이었다는 뒷이야기가 붙는다.

테제(해설의 도입):

> *"답은 더 좋은 에이전트가 아니었습니다. 에이전트가 일하기 좋게 조직과 개발 환경을 다시 짰습니다."*(00:15~00:19)

> **트랙과 인용.** Korean original + 영어 더빙(오디오 `ko` · `en` · `en-US`, 메타 `language`=`en`), `ko` = `ko-orig`(`kind=asr&lang=ko&variant=gemini`). `en-orig`는 내레이션 자리에서 영어 **더빙의 ASR** 이다(인용하지 않음, 판독 대조용 — *GB 300* 을 *GB200* 으로, *Devin Bots* 를 *Devin Boss* 로, *Walden Yan* 을 *Waldnia* 로 틀린다). **한국어 인용은 전부 ko-orig의 내레이션이다.**
>
> **발표 원음은 세 조각만 캡션에 있다.** 08:05~08:20 · 08:53~08:59 · 10:10의 영어가 ko-orig와 en-orig **두 트랙에 같은 글자로** 잡혔다. 앞의 두 조각만 인용한다(10:10은 문장이 끊겼다). ⚠️ 화자 표시는 없다 — 발표 발췌 자리라 Walden Yan의 말로 읽었다.
>
> ⚠️ **나머지 발췌 자리 열한 곳(합쳐 약 2분 50초)은 두 트랙 모두 무캡션이다.** 그 구간의 내용은 적지 않는다. **제목의 *노트북을 열지 않고* 와 설명란의 *아이패드로 개발하는 엔지니어* 가 나온 자리(04:14~04:25)도 그 안에 있다** — 캡션에 남은 것은 내레이션의 *아이패드가 더 안전하다는 말도 덧붙였습니다* 뿐이다.
>
> ⚠️ **해설이고 2차 전달이다.** 위키는 원본 발표도, 설명란의 글 다섯 편도 열지 않았다. 수치는 내레이션이 슬라이드와 글에서 옮긴 값이고, 전부 Devin을 파는 회사의 자기 보고다.

## 1. 엔지니어 2.7배, PR 40배 (00:00~00:27)

- 그래프: *"엔지니어는 2.7배 늘었습니다. 그런데 뭐지된 PR은 40배가 됐습니다."*(00:00~00:03)[=머지된]
- 해설의 환산: *"엔지니어 한 명이 10배를 해낸다는 뜻입니다."*(00:10~00:12) ⚠️ 40 ÷ 2.7은 약 15다 — *10배* 가 발표의 말인지 해설의 어림인지는 캡션으로 알 수 없다.
- 답의 방향: *"답은 더 좋은 에이전트가 아니었습니다. 에이전트가 일하기 좋게 조직과 개발 환경을 다시 짰습니다."*(00:15~00:19)
- 예고: *"끝에는 사람 승인 없이 PR 999개가 뭐지된 앱과 발표 나흘 뒤에 나온 뒷이야기도 있습니다."*(00:21~00:25)[=머지된]

## 2. 40배는 무엇의 40배인가 (00:27~01:23)

- 발표자: *"발표자는 월드 냰. 코그니션의 공동 창업자이자 최고 제품 책임자로 11월 12일 샌프란시스코 무대에 섰습니다."*(00:27~00:32)[=Walden Yan]
- 막대: *"파란 막대는 한 달 동안 뭐지된 PR 수입니다. 작년 11월을 1로 놓고 잰 배수입니다."*(00:34~00:39)[=머지된] 점선: *"바닥에 깔린 점선은 연구 개발 인력입니다. 같은 기간 2.7배가 됐습니다."*(00:40~00:44)
- 해설의 대조: *"인원 2.7배는 글로 확인되는 자료가 없습니다."*(00:45~00:47) 단서 하나 — *"올해 7월 월드 냰은 엔지니어가 70명 남짓이라 다들 놀란다고 썼습니다."*(00:47~00:52) ⚠️ 이어지는 발췌(00:55~01:08)는 무캡션.
- ⭐ 해설의 유보 셋: *"다만 여기서 세는 건 PR 개수입니다. PR 하나의 크기나 가치는 그래프에 나오지 않습니다."*(01:08~01:11) *"품질이 그대로라는 것도 발표자의 말입니다. 데빈을 파는 회사의 발표라는 점도 감안해야 합니다."*(01:13~01:16) → [[effort-output-outcome-mission]]

## 3. 기본값은 자율주행 (01:23~02:10)

- 첫째 변화는 *소프트웨어 공장* 이라는 생각이다: *"버그 신고가 들어오면 분류부터 구현, 테스트, 리뷰까지 데빈이 합니다. 배포와 장애 대응도 마찬가지입니다. 사람은 판단이 필요할 때만 불러옵니다."*(01:25~01:33) → [[software-factory]]
- ⚠️ 발표 발췌(01:36~02:05)는 무캡션. 내레이션이 받은 한 줄: *"설명할 수 있는 일은 결국 에이전트에게 갑니다."*(02:05~02:06)

## 4. 팀을 2~3명 포드로 쪼갰다 (02:10~02:52)

- 예전: *"예전에는 기획자, 엔지니어, QA와 온콜 담당이 역할별로 나뉘어 있었습니다."*(02:13~02:17)
- 지금: *"지금은 두 세 명 짜리 작은 팀, 포드로 쪼갰습니다. 결제나 모바일 앱처럼 제품 한 조각을 통째로 맡습니다."*(02:18~02:24)[=pod]
- ⚠️ 포드에 대한 발표 원음(02:26~02:52)은 무캡션 — 포드 안에서 누가 무엇을 하는지, 포드가 몇 개인지는 캡션에 없다. 설명란은 *2–3명짜리 포드가 버그 신고부터 QA까지 맡고* 라고만 적는다.

## 6. 에이전트가 혼자 테스트하는 코드베이스 (03:27~04:38)

- 예전: *"예전에는 클라우드의 스테이징 서버와 데이터베이스에 붙어서 테스트했고, 마지막엔 엔지니어가 직접 화면을 눌러봤습니다."*(03:41~03:46)
- ⭐ 지금: *"지금은 모든 서비스를 도커 컴포즈로 띄우고 외부 서비스는 흉내낸 가짜로 바꾸고 가상 머신 하나 안에서 돌립니다."*(03:48~03:53)[=Docker Compose]
- 환경의 유지: *"가상 머신은 매 시간 새로 만듭니다. 최신 코드를 받아 처음부터 빌드하고 빌드가 깨지면 데빈이 먼저 고칩니다."*(03:54~03:58)
- 테스트 방법의 유지: *"테스트하는 방법도 데빈이 스크립트 파일로 직접 적어둡니다. 코드가 바뀌면 그 스킬도 데빈이 고칩니다."*(04:00~04:03) → [[agent-verification-skill]]
- 해설의 대조: *"도커 컴포저 이전이나 매시간 재빌드는 발표에서만 나온 이야기입니다. 테스트 스킬은 코그니션이 5월에 블로그에도 적어 두었습니다."*(04:06~04:11)[=Docker Compose 이전]
- ⚠️ **제목의 근거가 되는 대목(04:14~04:25)은 무캡션이다.** 설명란: *코드 변경을 테스트하려고 노트북을 열 일이 없어져 아이패드로 개발하는 엔지니어도 생겼다고 합니다.* 캡션에 남은 것: *"아이패드가 더 안전하다는 말도 덧붙였습니다."*(04:25~04:26) 이유는 *"비밀 키가 개발자 노트북 여기저기 흩어져 있지 않으니까요."*(04:26~04:29)
- 여럿이 쓰는 기능의 시험: *"데빈은 가상 머신 하나에서 계정 여러 서로 같은 줌 통화에 들어가 음성을 주고받았습니다."*(04:32~04:36)[=계정 여럿으로(추정)]

## 7. 공장을 고치는 에이전트 (04:38~05:30)

- 기록: *"클라우드에서 돌린 세션은 코드 한 줄 결정 하나까지 기록에 남습니다. 그 기록 위에 다시 에이전트를 돌립니다."*(04:42~04:47)
- 슬라이드의 예: *"슬라이드의 예에서는 지난 세션 1,300여 개를 분석했습니다. 테스트할 때마다 되풀이되던 로그인을 스킬로 저장해 테스트 시간을 31% 줄였습니다."*(04:47~04:55) → [[run-trace-skill-distillation]]

## 위키의 읽기

- ⭐ **[[software-factory|소프트웨어 공장]]의 벤더 자기 보고가 하나 더 늘었고, 이번에는 *사람 승인 없는 머지* 의 숫자가 붙었다.** 1,134개 가운데 999개(약 88%). 이 위키의 공장 소스들은 대개 사람의 승인 지점을 남겨 두는데([[tech-bridge-lauren-tan-agents-merge-own-prs]]가 예외 쪽이다), 여기서는 새로 만드는 앱 하나에 한해 그 지점을 대부분 뺐다. ⚠️ 해설이 직접 짚듯 *어디까지 안전한지* 는 발표에 없고, 대상은 아직 공개 테스트 중인 신규 앱이다 — 기존 제품 코드에 같은 비율이 적용된다는 말은 없다.
- **40배는 [[effort-output-outcome-mission|산출]] 지표다.** PR 수는 Kent Beck의 사슬에서 앞쪽(노력 · 산출)에 있고, 해설도 *일의 양이지 가치가 아니다* 로 맺는다. 인원 2.7배는 글로 확인되지 않고 *품질은 그대로* 는 발표자의 말이다. 어제 [[tech-bridge-zechner-ronacher-verification-is-overrated]]의 *제품 코드를 100% AI가 쓴다는 회사들* 에 대한 단정과 나란히 읽을 자기 보고다.
- **병목을 모델이 아니라 환경에 둔다.** 모든 서비스를 한 가상 머신 안에서 띄우고 외부 서비스를 가짜로 바꿔 에이전트가 끝에서 끝까지 직접 돌려 보게 한다는 처방은 [[agent-verification-skill]]의 전제(에이전트가 자기 코드를 실제로 돌릴 수 있어야 한다)를 코드베이스 쪽에서 채우는 일이다. 테스트 스킬을 에이전트가 쓰고 고친다는 점이 더해진다.
- ***일감이 아니라 직무* 는 [[goal-level-delegation]]의 제품화다.** 사흘 전 [[tech-bridge-grok-bot-team-lightcone-ai-coworkers]]의 *작업 → 목표 → 일자리* 와 같은 사다리이고, 두 회사가 같은 주에 같은 말을 한다. 차이는 Cognition 쪽이 숫자 하나로 줄일 수 있는 일(P99 · 분당 토큰 · iOS와의 일치)을 조건으로 건다는 점이다.
- **이해관계.** 발표자는 Devin을 파는 회사의 공동 창업자이고, 발표는 나흘 뒤 본인이 밝혔듯 신제품의 예고편이었다. 해설은 이 점을 두 번 적고(01:15 · 09:05) 글로 확인되는 것과 발표에만 있는 것을 갈라 준다 — 위키도 그 구분을 따랐다.
- 페이지화하지 않음: Russell Kaplan(한 문장) · CoreWeave(발표문 출처로만) · AI Engineer Code Summit(행사 이름은 설명란에만 — [[ai-engineer]] 보강 없음) · 안드로이드 앱을 맡긴 엔지니어(이름 판독 불가) · Docker Compose · Kotlin · Vera Rubin(→ [[nvidia]]에 한 절).
