- 그래서: *"어려운 일에서 오퍼스를 하이 위로 올리기 전에 페이블을 먼저 시험해 보라."*(02:35~02:39)
- 가이드 표에서 Fable로 **시작** 하라는 일: 대규모 리팩터링 · 마이그레이션, 아키텍처 설계, 여러 서브에이전트 지휘, 깊이 있는 리서치와 과학 정량 분석.
- 3차원 작업 — Unity의 테스터: 3차원 장면을 처음부터 만드는 일에서 이전 모델과 차이가 가장 뚜렷했고, 어려운 게임 개발 작업에서 막히지 않고 계속 고쳐 나간다.

## 5. 지휘는 Fable, 일은 작은 모델 (03:03~04:50)

- 출시 글이 적은 역할 — 오케스트레이터: *"쉬운 일을 작은 모델에게 나눠 주는 지휘자입니다."*(03:04~03:08) (03:10~03:34 무캡션) → [[token-roles]]
- 사례: Anthropic 엔지니어 한 명이 빈 폴더에서 운영체제 시제품을 만들게 했다. *"페이블은 서브 에이전트 1,000개 이상을 지휘하며 8일 동안 쉬지 않고 일했습니다."*(03:43~03:47)
- 나누는 기준(가이드): *"파일 찾기, 테스트 실행, 로그 읽기처럼 틀려도 금방 티가 나는 일은 작은 모델에게 줍니다. 코드 수정과 판단은 메인 모델에 남깁니다."*(03:50~03:56)
- Claude Code에서는 서브에이전트 정의 파일에 한 줄(04:02, ASR *모델 하이쿠* → `model: haiku` 추정). → [[claude-haiku-5-5]]
- 놓치기 쉬운 것 — 기본 탐색 에이전트 **Explore**: *"요즘 버전에서는 늘 하이쿠로 돌지 않고 세션 모드를 따라갑니다. API 기준 상한은 오퍼스입니다."*(04:08~04:12)[=세션 모델을] 파일 검색에 Opus 값을 내기 싫으면 Explore라는 이름의 서브에이전트를 Haiku로 직접 정의한다.
- 서브에이전트는 공짜가 아니다 — 프롬프트 가이드는 세션 비용의 큰 부분이 될 수 있다고 경고한다. *"엔트로픽 테스트에서는 도구 설명에 서브 에이전트의 비용을 자세히 적자 띄우는 수가 절반 정도로 줄었습니다."*(04:25~04:29)
- 효과가 난 사례: 소스 코드 2,200만 토큰에서 결함을 찾는 시험 — Opus가 지휘하고 Sonnet 일꾼을 붙이자(04:37, ASR *25가지* → 25개 추정) Opus 혼자보다 1/3쯤 싸고 점수는 비슷했다.
- 한계: *"컨텍스트 창 하나에 들어가는 일이면 나누고 합치는 비용이 아끼는 것보다 큽니다."*(04:45~04:49)

## 6. 끝내기 전에 멈추는 Fable과 effort (04:50~05:56)

- 증상: *"페이블은 길고 단계가 많은 일에서 일을 끝내기 전에 턴을 마칠 때가 있습니다."*(04:50~04:54) 남은 일을 목록으로 적어 두거나, 계속할지 묻거나, 타임아웃 같은 흔한 장애물에서 멈춘다. low와 medium에서 더 잦다.
- 문제: *"그런데 클로드 코드의 기본 값이 바로 그 미디엄이라는 게 문제입니다."*(05:03~05:05)
- 해법 둘: ① 오래 혼자 돌릴 일 앞에서 effort를 high로 ② medium에 두고 가이드가 주는 문단(*시킨 일이 남아 있으면 멈추지 말라*)을 시스템 프롬프트에 넣는다.
- ②의 결과: *"미디엄으로 다시 돌린 테스트에서 덜 끝내고 멈춘 세션이 절반 정도로 줄었습니다."*(05:23~05:27) *"다만 남은 일을 적고 멈추는 경우는 못 막았고 출력 토큰은 30% 쯤 늘었습니다."*(05:28~05:32)
- high 위로 계속 올릴 일은 아니다 — 가이드는 성능 향상의 대부분을 high에서 얻는다고 적었다. high 이상에서는 인사 한마디에도 생각부터 하고 답한다 → 간단한 요청이 느려졌으면 그 턴만 내린다. extra high는 점수가 조금 오르고 토큰은 훨씬 많이 쓴다. *"하이를 넘으면 한 단계가 더 큰 모델 하나 값일 수 있습니다."*(05:52~05:54)

## 7. never와 go (05:56~07:09)

- 전제: *"페이블은 지시를 아주 꼼꼼하게 따르기 때문입니다. 예를 들어 네버가 들어간 지시는 예외 없는 절대 규칙으로 받아들입니다."*(05:58~06:04)
- 처방 ① *파일을 절대 지우지 마라* 대신 *지우기 전에 승인을 받아라* 로 쓴다 — 결정권을 사람에게 둔다는 뜻.
- 처방 ② 예전 세션에서 쌓인 메모와 규칙 — *절대 재시도하지 마라* 같은 낡은 지시를 계속 따른다. *"필요 없어진 메모는 지우고 승인 없이 해도 되는 단계는 하나하나 이름을 적어 주라고 합니다."*(06:19~06:23) → [[prompt-debt]]
- 처방 ③ 승인할 때 — *go* 한마디 대신 무엇을 허락하는지 정확히: *"네, 스테이징 데이터베이스에 마이그레이션을 돌리세요. 이런 식입니다."*(06:29~06:32)
- 승인 규칙도 구체적으로 — *대화 밖 사람에게 메시지 보내기* 를 승인 대상으로 적은 테스트에서: *"그러자 모델은 동료와 다른 팀에 보내는 일상적인 요청까지 절반쯤은 보류했습니다."*(06:39~06:43)
- 코드의 주인 — 아무 말이 없으면 중복이 생겨도 기존 구조에 덧붙이기만 했다. *이 코드베이스의 주인은 너* 라는 한 문장을 넣자: *"중복 코드를 하나로 합친 비율이 10% 미만에서 75% 쯤으로 뛰었습니다."*(06:57~07:00) 대가: 출력 토큰 70~80% 증가 + 시키지 않은 변경. 사용자의 코드를 최소한만 고쳐야 할 때는 뺀다.

## 8. 마지막 보고서 (07:09~07:54)

- *"긴 작업이 끝나면 사람이 보는 건 마지막 보고서 뿐입니다."*(07:09~07:11) 읽는 사람은 도구 호출도 파일도 본 적이 없다 → 보고서만으로 이해가 돼야 한다.
- 가이드의 문단: *"똑똑하지만 맥락을 모르는 독자를 위해 쓰고 핵심은 처음 몇 문장에 넣으라는 겁니다."*(07:21~07:25) → [[minimizing-reader-load]]
- Lydia가 보탠 두 가지 — ⚠️ 07:28~07:43 무캡션, 내용 미상.
- 믿지는 않는다: *"엔트로픽 테스트에서 페이블의 마무리 요약은 작은 변경을 자주 빠뜨렸습니다."*(07:45~07:49) → 요약만 읽지 말고 diff를 함께 본다. → [[agent-change-evidence]]

## 9. 모델을 바꾸는 순간 (07:54~08:16)

- *"프롬프트 캐시는 그걸 쓴 모델의 것입니다."*(07:56~07:57) 모델을 바꾸면 새 모델의 첫 턴에서 대화 전체의 캐시 쓰기 값을 다시 낸다. → [[prompt-caching]]
- 생각도 따라오지 않는다: *"페이블에서 다른 모델로 옮기면 페이블이 해둔 추론은 버려집니다."*(08:05~08:06)
- 그래서 작업이 한 덩어리 끝난 자리에서 바꾼다 — compact를 먼저 돌리거나 짧은 계획서를 들고 새 세션을 연다. → [[context-resets-and-compaction]]

## 10. 정리 (08:16~08:46)

- *"정리하면 셋입니다. 시작은 오퍼스 5.5 미디엄에서 페이블은 큰 일과 지위에 쓰고 오래 돌려둘 때는 하이로 올립니다."*(08:30~08:37)[=지휘에] *"그리고 예전 모델에 맞춰 쓰던 규칙과 메모는 다시 읽어 봅니다."*(08:38~08:40)

## 위키의 읽기

- ⭐ **열려 있던 *49.1 vs 45.3* 에 한 조각이 더 붙는다.** 11-10 발표문 해설은 Frontier Code 49.1을, Chase AI · 가이드 해설 · Theo 편은 Frontier Code 2.0 high 45.3%를 적어 *같은 표인지 미확인* 이었다([[fable-5-2]]). 이 해설은 49.1%를 소개한 뒤 *"아까 그 시험에서"* high로 돌린 점수가 45.3%라고 말한다 — **같은 시험의 다른 effort 값** 이라는 위키의 추정과 맞는 방향이다. ⚠️ 다만 49.1이 어느 effort의 값인지는 여전히 말하지 않고(Opus의 45.5가 max라는 것만 말한다), 해설자의 연결일 뿐 위키는 출시 글을 열지 않았다. *2.0* 이라는 판 표기는 이 편에 없다.
- ⭐ **권고가 서로 당기는 자리 — medium에서 시작 vs medium에서 일찍 멈춘다.** 가이드는 *Opus 5.5 medium에서 시작* 을 말하고, 프롬프트 문서는 Fable이 *low · medium에서 끝내기 전에 멈추는 일이 더 잦다* 고 한다. 해설의 화해는 **조건부** 다 — 평소는 Opus medium, *Fable로 오래 혼자 돌릴 때만* high. [[theo|Theo]]의 *high를 기본으로* ([[reasoning-effort-levels]])와는 여전히 다르다.
- **성질마다 크기가 붙었다**(모두 Anthropic 자체 테스트의 해설 전달). 11-12 Chase AI 편에 이미 있던 것은 *끝까지 하라고 적으면 멈춤이 약 절반* 하나이고, 이번에 그 대가(출력 토큰 +30%, 목록을 적고 멈추는 경우는 못 막음)가 붙었다. 새 값: 서브에이전트 비용을 도구 설명에 적자 띄우는 수 절반 · 승인 규칙이 넓으면 일상 요청 절반 보류 · 주인 문장으로 중복 통합 10% 미만 → 75%(출력 토큰 +70~80%). ⚠️ 표본 · 과제는 말하지 않는다.
- **이미 있던 것의 재확인**: 가격 $8 / $40 · 출력 최대 30% 빠름 · 차단 55% 감소 · OS 시제품 8일 · 서브에이전트 1,000개(11-10), 검증 → effort → 모델 사다리 · Explore는 세션 모델을 따른다 · 2,200만 토큰 결함 탐색 1/3 절감 · 캐시는 모델에 묶인다(11-13 가이드 해설). 새 조각은 **가격 인하 폭 20%**(*보도에 따르면*), **Explore의 API 기준 상한이 Opus** 라는 것, Sonnet 일꾼의 수(25, ASR 추정), **모델을 바꾸면 추론이 버려진다** 는 것.
- **never의 문제는 [[prompt-debt]]의 세 번째 얼굴이다.** 11-09 Lance Martin 편이 낡은 프롬프트를 빚으로 불렀고, 11-12 Chase AI 편은 Fable이 규칙을 글자 그대로 따라서 *행동* 이 굳는다고 했다. 이 편은 처방을 문장 수준으로 내린다 — 금지를 승인 절차로 바꿔 쓰고, 승인 없이 해도 되는 단계를 이름으로 적고, 승인의 말도 범위를 적는다.
- ⚠️ 도입부 실험(27분 vs 58분 · 토큰 7배)은 과제도 결과물의 질도 없는 일화다. [[theo|Theo]]가 측정한 *초당 토큰은 거의 같다*(106 vs 112)와 합치면 시간 차이는 속도가 아니라 **한 일의 양** 에서 왔을 것이다(위키 추정).
- 페이지화하지 않음: Frontier Code(벤치마크) · Unity · Explore 서브에이전트 · 오케스트레이터 구성 · X 사용자의 실험.
