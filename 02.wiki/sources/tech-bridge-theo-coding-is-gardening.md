# Tech Bridge — 개발자는 이제 정원사? Theo가 테스트 1만 1천 개를 지운 이유

[[tech-bridge|Tech Bridge]]의 **6:21 한국어 해설, 공식 챕터 9.** 개발자이자 유튜버 [[theo|Theo]](t3.gg)의 영상 *"Coding Isn't About Code Anymore"*(`GtJKFhztgdM`)를, T3 Code 저장소(`pingdotgg/t3code`)의 실제 PR과 해설자가 직접 집계한 머지 그래프로 정리한다. 내레이션은 AI 음성이다(설명란). Theo 원음으로 보이는 발췌 다섯 곳은 **두 자막 트랙 모두 무캡션**이다. **위키는 원 영상 · PR · Lauren의 게시물을 열지 않았다.** raw: `01.raw/articles/2026-11-10_개발자는 이제 엔지니어가 아니라 정원사 Theo가 테스트 1만 1천 개를 지운 이유 6분 정리 (T3 Code).md`.

테제(해설이 전하는 Theo의 말):

> *"모든 팀에는 정환사가 필요하다. 뽑은 잡조 하나하나가 규칙이 되어 다시는 자하지 못하게 하는 사람 말입니다."*(05:43~05:50)[=정원사 · 잡초 · 자라지]

> ⚠️ **한 사람의 경험담을 해설자가 옮긴 2차 전달이다.** 수치(1만 1천 개 · 25만 줄 · 43% · 59% · 네 개 · 2만 5천 줄)는 해설이 전한 PR 내용이고 위키는 PR을 열지 않았다. 하루 머지 PR 그래프는 **해설자 자신의 집계**(설명란 *"GitHub API로 … 직접 집계(UTC 기준)"*)이고 Theo의 주장이 아니다. 인과(*정원이 건강해서* 머지가 늘었다)는 Theo의 해석이다.
>
> **트랙과 인용.** `ko` · `ko-orig`가 md5 동일(원 ASR)이고, en-orig는 영어 더빙이다. 인용은 전부 ko-orig다. ASR이 *PR*을 *피아 · 피이 · 피할수* 로, *Theo*를 *태오 · 태우 · 헤오* 로 적는다. 판독 목록은 raw 헤더에 있다.

## 1. 테스트 1만 1천 개를 지운 PR (00:00~00:38)

- *"하나로 테스트 11,000개를 지웠습니다.지 코드는 25만 줄이 넘습니다."*(00:00~00:03)[=PR 하나로 · 지운 코드는] *"AI가 코드를 쏟아내는 시대에 안전 장체를 오히려 걷어낸 겁니다."*(00:03~00:07) 같은 저장소에는 하루에 머지되는 PR이 수백씩 쌓이고 있었다(00:07~00:11, 더빙의 *issues* 는 따르지 않음).
- 00:14~00:27 무캡션 발췌 뒤: *"그는 이제 개발자가 정원사가 됐다고 말합니다. 테스트를 지우는게 왜 정원 일일까요?"*(00:29~00:33)

## 2. 블록 놀이가 사라진다는 두려움 (00:38~00:55)

- *"알맞은 조각을 찾아 알맞게 끼워 맞추는 재미죠. AI로 코딩하면 바로 그 재미가 사라질 것 같았고"*(00:39~00:46) 그런데 요즘은 *"일주일에 한두 번 새벽 6시에 잠들만큼 재밌다고 합니다."*(00:48~00:52)

## 3. Twitch — 30분 만에 올라온 PR 두 개 (00:55~01:54)

- 2017년부터 4년 Twitch 근무. 기능을 맡는 제품 팀과 그 밑을 받치는 플랫폼 팀이 따로 있었고, Theo는 제품 팀이면서 플랫폼 팀 회의에 늘 끼어 있었다(00:57~01:09).
- ⭐ 일화 1: 새 문서를 그대로 따라 올린 PR이 썩 좋지 않았다. 플랫폼 팀원이 이유를 묻고 돌아가더니 *"30분 만에 피 두 개를 올렸습니다. 헷갈리게 만든 문서를 고치고 헷갈리게 만든 코드를 고친 거죠."*(01:21~01:27) 교훈: *"나쁜 피이 올라왔다는 건 다음 사람이 [음악] 같은 실수를 하지 않게 고칠 기회라는 겁니다. 증상 말고 원인을 고쳐라."*(01:27~01:33)
- 일화 2: 대시보드 레이아웃 저장 문제로 복잡한 노드 구조를 만들자던 중, GraphQL 팀에 직접 물었더니 *"그냥 제이슨으로 저장하면 되잖아요."*(01:45~01:46)[=JSON]
- ⭐ *"개발자가 겪는 마찰의 상당수는 대화 한 번과 플랫폼에 작은 변경 하나면 사라진다. 태오가 트위치에서 배운 겁니다."*(01:46~01:53)

## 4. 혼자 세운 회사 — PR의 절반은 아무도 못 느낀다 (01:54~02:14)

- 회사를 차리자 플랫폼 팀이 사라졌다 — *"직원 1500명 회사에서 혼자인 회사로 간 거죠."*(01:58~02:00)
- ⭐ *"절반은 제품 기능에 절반은 플랫폼을 다듬는데요. 그가 올린 PR의 절반은 사용자 눈에 아무 차이가 없었습니다. 대신 그 PR들이 나머지 절반을 훨씬 쉽게 만들었습니다."*(02:03~02:13) → [[codebase-gardening]]

## 5. 내 슬롭이 팀을 막고 있었다 (02:14~02:57)

- T3 Chat의 데이터 동기화 엔진을 손으로 짰다. *"돌아가긴 했지만 유지보수는 지옥이었죠. 그 코드를 아는 사람은 태오 한 명뿐이라 팀원들은 늘 그를 기다려야 했습니다."*(02:19~02:25)
- 한 달 들여 다른 구현(ASR *컴백스*, Convex 추정)으로 옮겼다 — 2만 5천 줄 넘는 PR, 사용자는 거의 차이를 못 느꼈지만 *"팀원들이 올리고 머지하는 피이 눈에 띄게 들었습니다."*(02:32~02:35)[=PR이 · 늘었습니다]
- ⭐ *"그는 에이전트보다 먼저 슬롭을 쓰고 있었던 겁니다."*(02:37~02:39) 02:42~02:47 무캡션 발췌 뒤: *"사람이 남긴 슬롭이 팀원을 막았듯 이제는 이전 모델이 남긴 슬롭이 다음 모델을 막는다는 얘기입니다."*(02:51~02:55) → [[ai-slop]]

## 6. 계산이 바뀌었다 — 한 달짜리 일이 프롬프트 하나로 (02:57~03:53)

- Twitch 시절 Apollo GraphQL 2 → 3 업그레이드: 깨진 TypeScript 파일 수천 개를 구글 시트에 올리고 자원자들이 알파벳 순으로 나눠 손으로 고쳤다 — *"여덟 명 남짓이 한 달 넘게 매달린 일입니다."*(03:08~03:09) 03:14~03:20 무캡션 발췌.
- ⭐ 대비: Twitch에서는 600~800명이 쓰는 도구라도 다시 쓰는 건 *"본전이 안 맞았습니다. 그런데 지금 태오는 세 명짜리 팀을 조금 더 빠르게 하려고 타입스크립트를 러스트로 다쓰고 있습니다."*(03:24~03:30)[=다시 쓰고] → [[rust]]
- ⭐ 계산이 바뀐 둘째 이유: *"마찰은 사람보다 에이전트를 훨씬 세게 막습니다. 개발 서버가 뜨는데 5분이 걸리면 에이전트는 확인할 때마다 5분씩 멈춥니다. 캐시 유지 시간이 5분이면 그 사이 캐시도 놓치고요."*(03:34~03:45) *"느린 개발 서버, 느리고 무거운 C로는이를 병렬로 돌리기 어렵고 릴리스가 두려우면 머지 버튼을 덜 누르게 됩니다."*(03:45~03:52)[=CI로는 일을] → [[agent-friction-multiplier]](신규) · [[prompt-caching]]

## 7. 슬롭은 잡초보다 빨리 자란다 — 테스트 43% 삭제 (03:53~04:55)

- 03:54~04:05 무캡션 발췌 뒤: *"그래서 태오는 우리 일이 정원 일이라고 말합니다. 걸음을 주고 지대를 세우고 잡초는 보이는 잭시 뽑는 일이죠."*(04:05~04:10)[=거름 · 지지대 · 족족(추정)]
- 처음의 PR이 잡초 뽑기였다: *"테스트가 너무 많고 시끄러워서 릴리스 실행이 불안정한 테스트 때문에 대부분 실패했거든요."*(04:13~04:18) → [[structure-sensitive-tests]]
- ⭐ 누가 골랐나 — *"클로드 하이코 에이전트 때가 모든 테스트 파일을 하나의 기준으로 읽었습니다."*(04:20~04:25)[=Claude Haiku 에이전트 떼] *"파일 절반 가까이는 두 번씩 따로 판정해 둘 다 동의할 때만 지웠고 의견이 갈린 1900권은 세 번째 하이코가 정했습니다."*(04:25~04:32)[=1,900건] → [[generator-evaluator-pattern]](독립 판정 · 합의, 위키의 읽기)
- 결과: *"테스트 25,900여개 가운데 약 1만1,000개 43% 삭제 테스트 파일 실행 시간 합은 59% 줄었습니다."*(04:32~04:40) *"지온 테스트가 잡았을 회기는 아직 없었고 머지 뒤 되살린 건이네 개뿐이었습니다."*(04:40~04:46)[=지운 테스트가 잡았을 회귀 · 되살린 건 네 개]
- 재발 방지: *"나쁜 테스트가 보이면 그걸 쓴 에이전트에게 왜이 테스트를 넣었는지 묻고 그 뿌리를 고칩니다."*(04:48~04:54) — §3의 *증상 말고 원인* 이 에이전트에게 옮겨 간 형태다.

## 8. PR마다 붙는 작은 검사 하나 — 지지대 (04:55~05:25)

- 서버 → 휴대폰 데이터를 몇 킬로바이트까지 줄여 놨는데 사소한 PR들이 자꾸 다시 늘렸다. ⭐ *"PR마다 실제 대화 데이터를 흘려보내 전송량을 재고 결과를 PR 댓글로 남기는 검사를 만들었습니다. 기준을 넘으면 빨간 X가 뜹니다."*(05:05~05:11)
- *"무엇보다 에이전트에게 이건 우리가 신경 쓰는 숫자라고 알려줍니다. 식물이 그쪽으로 자라도록 옆에 꽂는 나무 지지대인 셈이죠."*(05:15~05:24) → [[hard-vs-soft-enforcement]] · [[executable-standards]]

## 9. 정원이 건강하면 (05:25~06:21)

- 해설자의 집계: T3 Code의 하루 머지 PR — *"봄부터 여름까지 하루 평균 수십개도 안 되던 숫자가 10월에는 하루 평균 130개를 넘고 많은 날은 수백개에 이릅니다."*(05:30~05:37) Theo의 해석: *"이게 정원히 건강해서라고 말합니다."*(05:40)
- *"리액트 컴파일러 팀의 로렌도 같은 비율로 있었죠."*(05:42~05:43) — [[lauren-tan]](설명란 *Lauren(@poteto)*), *비율 / 비유* 미확정 → 위 테제.
- 05:58~06:08 무캡션 발췌 뒤 맺음: *"코드를 직접 키우는 사람에서 코드가 잘 자라는 정원을 갖꾸는 사람으로"*(06:08~06:10) Theo는 지금이 일하면서 가장 재밌는 때라고 말한다.

## 위키의 읽기

- **[[codebase-gardening]]의 두 번째 1인칭 실무자.** 이 개념은 [[lauren-tan]]이 *안티패턴은 바이러스처럼 퍼진다 · 팀에는 정원사가 필요하다* 로 세웠다. Theo는 같은 은유를 쓰되(해설상 Lauren을 직접 언급) **구체적 손질 세 가지**를 붙인다 — 거름(플랫폼 작업 반반), 지지대(PR마다 붙는 수치 검사), 잡초(테스트 대량 삭제). 특히 **테스트를 지우는 것**을 정원 일로 본다는 점이 새롭다. 위키의 다른 소스들은 주로 *더 많은 검사* 쪽이었다.
- **슬롭은 사람 것도 모델 것도 다음 작업자를 막는다.** [[ai-slop]]의 *"AI 슬롭 이전에 인간 슬롭이 있었다"*(Lauren Tan)와 같은 방향이고, 이 소스는 **세대 간** 형태를 더한다 — 이전 모델의 슬롭이 다음 모델을 막는다.
- **마찰의 비용이 에이전트에게서 곱해진다.** 5분 개발 서버 · 5분 캐시 TTL · 무거운 CI가 사람에게는 불편이지만 에이전트에게는 *매 확인마다* 드는 비용이다. 그래서 *본전이 안 맞던* 재작성(TS → Rust)이 이제 맞는다 → [[agent-friction-multiplier]](신규) · [[rust]]의 *어려움의 부호가 바뀌었다* 와 같은 결론, 다른 이유.
- **⚠️ 인과는 미확인.** 머지 PR 증가는 테스트 삭제 · 지지대와 시기가 겹친다는 것만 보인다(해설자의 집계). 다른 원인(팀 증원 · 모델 교체 · 자동 PR)은 논의되지 않는다. 테스트를 *지운 뒤 회귀 없음* 도 Theo의 진술이고 기간이 짧다.
