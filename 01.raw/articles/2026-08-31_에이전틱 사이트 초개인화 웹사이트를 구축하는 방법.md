## 에이전틱 사이트가 해결하려는 문제와 목표 (00:00)

발표자는 Adobe에서 **Adobe Experience Manager**(콘텐츠 관리 제품) 수석 과학자. 커리어는 오픈소스 재단·프로젝트 기여.

에이전틱 사이트란 웹사이트를 탐색하는 **사용자의 의도를 파악하는 사이트**다. 사용자가 무엇을 하고 있고 무엇을 달성하려는지 파악해, 현재 브라우징 방식에 맞춰 페이지를 실시간 개인화한다. 목표는 마케팅 팀의 참여도·전환율.

스택: **AEM Edge Delivery**(콘텐츠가 엣지에 배치되는 제품 부분) + 여러 LLM 제공업체를 쓰는 백엔드 서비스. 빠른 추론에 **Cerebras**, 그 외 **Bedrock** 등도 시도.

## 전체 페이지가 아닌 블록 단위 개인화 (02:07)

개인화 엔진은 **블록**을 사용한다. 사이트의 각 블록이 사용자 페르소나에 따라 맞춤 설정된다.

> 사이트 전체를 새로 생성하는 것을 원하지 않습니다. 마케팅 담당자들과 이야기를 나눠보면, 그들은 매우 엄격한 브랜드 가이드라인을 가지고 있습니다.

## 기존 사이트 기반의 RAG 그라운딩으로 환각 방지 (03:13)

개인화되는 것은 사이트의 각기 다른 섹션이고, **사이트 전체를 코퍼스로 활용해 RAG를 구축**한다. 그래서 생성된 결과가 기존 사이트에 근거한다.

풀려는 문제는 "하나로 모든 것을 해결"의 반대 — 초개인화된 경험 + 수천 가지 사이트 버전을 손으로 만들지 않는 자동화된 콘텐츠 제작.

데모 가능한 예: 즉각적인 페르소나 적용, 검색 시 쿼리 생성과 결과 페이지 맞춤화, 일정 시간 탐색 후 관심사를 예측한 추천 페이지 생성.

마케터는 **자연어로 전략을 정의**하고 분석으로 개인화를 추진·조정한다. 발표자 표현으로 그것도 하나의 루프.

## 블록 기반 동적 프론트엔드 아키텍처 (04:24)

프론트엔드는 블록으로 구성된 동적 구조. Edge Delivery Services로 블록을 조합하고 AI가 실시간 업데이트한다.

백엔드에서는 모델과 제공업체를 평가한다. **깨달은 것 하나는 이것이 사이트마다 매우 다르다는 점.**

## 사이트별 모델 정확도 및 속도 평가 (05:33)

수많은 프롬프트로 여러 모델·제공업체를 테스트하고 정확도와 속도를 본다. 결과는 사이트 규모, 타겟 고객층, 상거래 유형에 따라 크게 달라져서 **평가를 지속적으로 실행**한다. 도구는 **promptfoo** — 여러 모델 제공업체와 로컬 모델, OpenAI 호환 제공업체를 대상으로 프롬프트를 평가.

중요하게 보는 두 가지:
1. **정확성**
2. **속도** — 사이트 생성에 1~2초 이상 걸리지 않는 것이 목표

사이트가 빠를수록 전환율·UX가 좋다는 것은 이미 입증돼 있다는 근거.

## 1.1초 vs 4.6초: 초고속 추론 성능 비교 (06:45)

예시 사이트에 프롬프트 15개.

> at the top you can see with Cerebras on the Gemma 4 model that was announced last last week, we can get an average latency of 1.1 seconds generating a page. You can compare that to the second one, which is 4.6 seconds, right? So, the difference is huge.

제공업체마다, 모델마다 속도가 다르다. 하단의 다른 것들도 **완벽할 필요는 없고 충분히 빠르면 충분**하다는 판단이 필요.

## 프론티어 모델이 필요 없는 이유 (07:54)

> 이런 종류의 작업을 하는 데에는 거대한 LLM이 필요하지 않습니다.

텍스트를 생성하고 **블록을 어디에 배치할지, 웹사이트를 어떻게 구성할지 결정**하는 일이라 많은 정보가 필요하지 않기 때문.

## 탐색 신호 기반 For You 페이지 사전 생성 (09:03)

브라우징 활동과 검색어가 기록되어 LLM 입력으로 들어간다. 예시에서는 페르소나 기반으로 히어로 카드, 제품, 블로그 피드, 내비게이션, CTA 버튼을 개인화.

추천 페이지는 **미리 생성**할 수 있다. 사용자가 탐색하는 동안 신호를 모아 계속 생성하므로 이 경우엔 속도가 덜 중요하다. 다만 여러 번의 LLM 호출에 따른 **비용 영향**은 고려 사항.

## 마케터가 직접 정의하는 페르소나와 개인화 루프 (10:10)

쿼리를 페르소나 또는 의도 유형별로 그룹화한다 — 이 사람은 사려는 것인가 정보를 얻으려는 것인가. 마케터가 그룹의 종류와 개수, 응대 방식을 정하고 AI가 그 그룹에 맞는 블록과 제안을 고른다.

조정 가능한 것: 블록 종류, 블록 순서, 미디어. 발표 전후로 나온 **"나노바나나 라이트"** 류 모델이면 이미지도 실시간 생성 가능하다고 언급 — 다만 품질·브랜드 이미지에 달렸다는 단서.

예시 사이트는 제품 페이지·가이드·경험담·블로그를 갖추고 있고, **LLM의 모든 반응이 이 사이트에 근거**한다. 맞춤형 제품 비교도 가능.

브라우저 계층에서 신호를 수신하고 백엔드가 LLM 호출 + 사이트로 구축한 RAG로 생성을 수행. 벡터 DB, 추론 메커니즘, Experience Manager가 필요하고 엣지 서버가 페이지·정적 콘텐츠를 제공. 백엔드 일부는 Google, 일부는 Cloudflare에서 실행.

## 단 한 명의 고객(Audience of One)을 위한 개인화 (12:31)

> 마케팅 담당자들은 항상 각 개인에게 맞춤형 서비스를 제공하는 것을 꿈꾸기 때문입니다. 그래서 저희는 그걸 '관객 한 명'이라고 부릅니다.

## 라이브 데모: 사용자 신호 수집과 맞춤 추천 (13:40)

완전히 생성된 예시 사이트(커피 머신)에서 이야기와 제품을 둘러본다. 디버깅 도구를 열면 하단에 **웹 브라우징이 보내는 신호**가 보인다 — 탐색 중인 카테고리 분류, 방문한 페이지 목록, 각 페이지 체류 시간. 이 데이터가 LLM 과정에 들어간다.

이동하면 검색 기록 기반으로 **이미 생성된 추천 페이지**가 표시된다.

## 캠핑용 커피 머신 검색 및 실시간 맞춤 페이지 생성 (14:56)

"캠핑 중에 커피를 준비할 커피 머신"을 검색하자 사이트가 그 자리에서 생성된다. 맞춤 텍스트는 캠핑이 일상 루틴을 포기한다는 뜻은 아니라는 카피와 캠핑용 추천 제품.

## 실시간 모델 변경 및 추론 속도 검증 (16:07)

디버그 모드 수치:

> Total time 164 seconds to generate the page. So, this includes a round trip to the LLM. This is using Cerebras Gemma 4. ... we get 2,300 tokens per second
> And if I run it again ... the LLM time is 1 second, and again, 2,200 tokens per second.

> ⚠️ "164 seconds"는 ko·en-orig 자막 모두 같지만 같은 화면의 LLM 왕복 1초·2,200~2,300 tok/s와 모순된다. 화면 판독 단위(ms 등)가 불명확하므로 **페이지 생성 시간으로 인용하지 말 것**. 신뢰 가능한 수치는 promptfoo 평가의 평균 1.1초(06:45)와 LLM 시간 1초.

고객 데모용으로 모델·온도·토큰을 바꿔가며 수동 확인도 가능하다 (promptfoo 자동 테스트 외에).

## 모든 웹사이트를 1시간 만에 에이전틱 사이트로 변환하기 (17:16)

> we built this tool that generates an agentic site for any site we want. So, if somebody wants to have a demo for a customer, come here and enter the URL. In less than an hour, you have an agentic site.

지난주 AI 엔지니어링 컨퍼런스 사이트로 시도해 검색창이 있는 사이트를 얻었고, "유럽 AI 컨퍼런스" 질의에는 유럽 컨퍼런스 중심 페이지가, 두 컨퍼런스 비교 요구에는 나란히 비교하는 페이지가 생성됐다.

## 음성 기반 초개인화와 웹의 미래 (18:29)

생성형 사이트로 청중 한 명을 상대할 수 있다면 그것이 웹의 미래일 수 있다는 관측. 개인 비서에게 "이걸 사고 싶어요"라고 말하고 거실 TV에서 완전히 맞춤화된 답을 받는 그림 — 전화도 컴퓨터도 필요 없고 목소리와 표시 장치면 충분하다는 것.

마무리:

> 제가 보여드리고자 했던 것, 그리고 이번 강의에서 여러분이 기억하셨기를 바라는 것은, 이제 이것이 가능하다는 것입니다. 앞으로는 점점 더 좋아질 거예요. 가격은 앞으로 더 저렴해질 겁니다. 속도는 앞으로 더 빨라질 겁니다.

의도 기반 접근 — 내 사용자는 무엇을 하려 하는가, 무엇을 사고 싶어 하는가 — 으로 그들을 위한 페이지를 따로 만들 수 있다.
