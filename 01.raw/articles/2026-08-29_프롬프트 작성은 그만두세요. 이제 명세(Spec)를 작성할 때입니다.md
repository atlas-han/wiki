> 영어 강연 + 한영자막 재배포. 아래는 **en-orig 자동 자막**을 중복 제거·문단 재구성한 캡처. ASR은 발표자명을 "Luna Diva", Spec Kit를 "Spekit", MCP를 "Motor Cortex Protocol"로 읽는다.

## 테제

프롬프트를 메인 아티팩트로 두지 말고, **명세(specification)를 메인 아티팩트**로 둔다. Prompt-first는 시작을 빠르게 했지만, 큰 프로젝트·엔터프라이즈·다인 팀에서 프롬프트는 사적·일시적·리뷰 불가하고, 빌드는 되지만 요점을 빗나가 오후를 날리기도 한다.

## 멘탈 모델

Constitution(팀/프로젝트보다 클 수 있는 must-have: testable by design, 보안, 엔터프라이즈 가이드) → Spec(what/why만, how 금지) → Plan(스택·배포·버전) → Task(구현 순서 청크) → Implement. 시작용 네 단계이지 전체가 아니다. **AI가 뱉은 constitution/spec/plan을 팀이 읽고 동의할 것.** 스펙은 Git history의 일부, 다음 기능의 출발점.

## 데모: Build 2026 세션 플래너 MCP

빈에 가까운 레포에서 `specify init` + Copilot integration + PowerShell. `.specify/`는 마법이 아니라 마크다운과 스크립트.

Constitution 여섯 원칙: grounded only, time-aware, agent-safe, HTTP-safe, testable by design, privacy by default.

Specify: 세션 JSON 접근, 검색/단건/현재 세션 MCP 도구. 구현 세부 없음. 모호하면 질문.

Plan: TypeScript, Node, HTTP transport. 버전을 안 적으면 모델이 채움.

Tasks는 페이즈·스토리 마크다운. Implement는 코드+테스트. MCP Inspector로 `search session` → 오프닝 키노트. 작동하는 서버가 나왔다.

## 세 가지 실천

워크플로 전체를 내일 바꾸지 말 것. 작고 의미 있는 실제 기능 하나: (1) 프롬프트 전에 스펙(what/why), (2) constitution에 비협상 규칙 2–5개(living document), (3) 산출 문서 전부 리뷰 후 구현.
